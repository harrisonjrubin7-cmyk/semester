# CC-1460 · Add the access-policy baseline and its tests as policy-as-code

## Summary

Adds `infra/policy/access.rego` and `infra/policy/access_test.rego`: the
eight-condition access baseline that `packages/platform/src/policy/engine.ts`
is measured against, with a deny set naming the failed condition. Nothing
reads these files at runtime and no deployment consumes them. They are checked
by `opa test infra/policy` in `scripts/infra/policy.sh`.

## Environments and tenants affected

None. No root is planned or applied by this change, and no tenant can observe
a difference. The policy evaluator the gateway runs is unchanged.

## Risk

The baseline could drift from the TypeScript evaluator without anything
failing, because the two are compared by review, not by a shared test. The
policy tests would not notice. It would be found by reading both files side by
side, which is why the file header says the TypeScript engine is the evaluator.

## Rollback

Delete the two files in a follow-up pull request. Nothing depends on them, so
the change takes one commit and under a minute, and the schema and runtime are
untouched.

## Evidence

`opa test infra/policy` passes 62 of 62 in the pull request's head.
