# CC-1728 · Maintain Course Engine API dependencies

## Summary

Dependabot receives a dedicated weekly pip-ecosystem updater for the Course
Engine API's PEP 621 `pyproject.toml` manifest. Minor and patch updates are
grouped, major updates remain isolated, and repository tests fail if the
updater loses its directory, ecosystem, cadence, pull-request bound or grouped
update types.

## Environments and tenants affected

None. This change alters candidate update configuration, tests and controlled
documents only. It does not deploy Course Engine, publish a course, activate a
tenant, change credentials, connect an institution or use institutional data.

## Risk

The updater may open future pull requests proposing changes to declared Python
dependency ranges. The bounded queue, grouped minor/patch changes, isolated
major changes, dedicated Course Engine CI and review are compensating controls.
The API has no committed resolver lock, so transitive dependencies continue to
resolve afresh and reproducibility remains an open gap. The standalone Zite RLS
verifier remains outside recurring update coverage, and TR-15 remains open for
that tree plus seven inline Edge Function handlers without executable behavior
tests.

## Rollback

Revert PR #1728 to remove the Course Engine API updater and its repository
guard. No infrastructure state, credentials, tenant data, course publication or
running service needs restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1728
- `app/src/lib/dependencyupdates.test.ts` checks the Course Engine API manifest,
  holds the updater contract and mutation-tests directory, ecosystem, cadence,
  queue bounds and grouped update-type failures.
- Local controls passed: 4 focused files and 70 tests; the full application
  suite passed 1,603 files and 25,070 tests, with 2 files and 81 tests skipped;
  app lint passed with the existing warning set; Dependabot YAML parsing and
  `git diff --check` passed.
- A fresh Python 3.12 environment resolved the API's currently declared ranges.
  Ruff passed for the API, tests and worker, and the SQLite suite passed 97
  tests plus 41 subtests. This is compatibility evidence for the resolution at
  test time, not a reproducible lock or a PostgreSQL result.
- The dedicated Course Engine workflow runs the API suite against SQLite and
  PostgreSQL when Course Engine files change. This configuration-only stacked
  candidate does not itself trigger that path-filtered workflow, so local
  compatibility and hosted repository checks remain distinct evidence.
- Hosted exact-head CI, CodeQL and HawkScan remain required before handoff.
