# CC-1730 · Execute the productivity source-check guard

## Summary

The productivity source-check Edge Function now delegates request handling to
an importable handler. Executable tests reject missing, invalid and unreadable
sessions before DNS or outbound fetch, refuse missing deployment
configuration, block private DNS answers and preserve the bounded public-source
check. The trust register moves this one function from an ordered source
mutation contract to direct handler coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, call a published runtime, use institution data,
change credentials, activate a tenant or alter a persistent database.

## Risk

The handler boundary is executed locally, but the hosted function and its
environment are not. Six Edge Functions still rely on ordered source mutation
controls instead of direct handler tests. Required-check enforcement, resolver
locks, authenticated target validation, independent review, accessibility,
TR-26 and the Operations Console synthetic/demo boundaries remain open.

## Rollback

Revert PR #1730 to restore the inline handler and the prior 11-direct/7-source
trust-register counts. No infrastructure, credentials, tenant data or running
service needs restoration.
