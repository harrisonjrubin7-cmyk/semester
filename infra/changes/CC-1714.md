# CC-1714 · Make high and critical dependency advisories block candidate CI

## Summary

The main CI workflow changes its application dependency audit from a
report-only step to a blocking gate for high and critical npm advisories. A
security-owned exception may pass only when npm reports no available fix and
the entry carries review and expiry dates. A planted high advisory proves the
gate turns red. This record applies nothing to a Terraform root or runtime.

## Environments and tenants affected

None. The workflow reads the candidate repository and npm advisory service. It
does not deploy, change infrastructure, contact a tenant or alter production.

## Risk

An advisory published after a lockfile was written can stop unrelated candidate
work. That is the intended fail-closed behavior. A malformed audit response or
exception also fails the job and is visible in the CI log within the same run.

## Rollback

Revert PR #1714 to restore the prior report-only audit step and remove the
exception evaluator. No infrastructure state or tenant data needs restoration;
the source rollback takes one pull request.
