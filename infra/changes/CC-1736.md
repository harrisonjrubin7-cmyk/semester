# CC-1736 · Execute the LTI launch boundary

## Summary

The LTI launch route now delegates its credential boundary to an importable
request authenticator. Executable tests prove that a non-POST request, missing
state, missing token, an unspendable or replayed state, a missing registration,
and failed header, signature or claim verification all stop before protected
launch work. An accepted launch is returned only after the state is spent and
the registration and signed token have been verified.

This replaces the final ordered source-mutation contract. All eighteen Edge
Functions now name direct executed behavior proofs in the repository.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not register an LMS, deploy the LTI function, call a platform JWKS, mint
a real session, write a score, use institution data, change credentials,
activate a tenant or alter persistent data.

## Risk

The importable boundary preserves the existing route order and refusal words,
but no authenticated published LTI runtime or real LMS platform is exercised.
Required-check enforcement, resolver and egress locking, authenticated target
validation, independent review, accessibility debt, TR-26 and the Operations
Console production-evidence boundary remain open.

## Rollback

Revert PR #1736 to restore the inline launch boundary and the prior
17-direct/1-source trust-register state. No infrastructure, credentials,
tenant data or running service needs restoration.
