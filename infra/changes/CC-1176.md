# CC-1176 · Name `shell: bash` on two steps that pipe into `tee` or `gzip`, so a failure in the first command fails the step

## Summary

`infra-apply.yml` (the `terraform plan … | tee plan.txt` step) and
`supply-chain.yml` (the deterministic bundle, `tar … | gzip`) gain
`shell: bash`. A step with no `shell:` runs as `bash -e {0}`, which has no
`pipefail`, so a failing `terraform plan` or `tar` upstream of the pipe was
reported as success. With `shell: bash` the step runs `-eo pipefail`. No
Terraform, policy, ruleset or permission changes; the same commands run. The
same defect in `contrast.yml` is the reason for the pull request, and
`workflowshell.test.ts` now requires the rule of every workflow.

## Environments and tenants affected

None. No tenant can notice. Nothing is applied when this merges.

## Risk

A plan or bundle that was failing silently will now fail the step. For
`infra-apply.yml` that is the point (an apply gated on a plan that did not
succeed); it runs from main only, so a first red run is visible in the Actions
tab within minutes. `supply-chain.yml` could turn red on the next main push if
the bundle was already failing.

## Rollback

Remove the `shell: bash` line from the two steps. Nothing was applied, so there
is no infrastructure state to unwind.

## Evidence

`workflowshell.test.ts` shown red against the original three workflows and
green after; `scripts/infra/policy.sh` and the infrastructure suites green on
this branch. See the pull request.
