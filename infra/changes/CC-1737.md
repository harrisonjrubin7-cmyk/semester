# CC-1737 · Schedule the text-spacing accessibility sweep

## Summary

The existing fail-closed WCAG 1.4.12 text-spacing browser sweep now runs in
the nightly accessibility workflow after the contrast, action-hierarchy and
target-size instruments. It runs even when an earlier sweep fails and retains
its output with the other accessibility logs. A repository contract test
holds the schedule, pipe-failure behavior, WCAG override values, planted
control, default widths and incomplete-walk refusal.

The first exact-head hosted run also exposed two calendar `MOVE` controls that
fell from the WCAG 2.2 AA 24-pixel minimum to 23 pixels in Tight density. The
shared control style now keeps a 24-pixel minimum height, with a source
contract and a real-browser calendar sweep covering both widths and all three
density settings.

TR-26 remains open. This increment covers each registered destination's
default synthetic state at phone and desktop widths; it does not cover
signed-in, error, modal, tablet or real-device states, and it does not detect
overlap between separate text boxes.

## Environments and tenants affected

None. The change schedules a synthetic browser instrument in GitHub Actions.
It does not deploy the app, use institution data, change credentials, activate
a tenant, alter DNS, publish a conformance claim or modify persistent data.

## Risk

The nightly workflow gains an additional browser walk and may run longer. Its
sixty-minute timeout remains in place. A failure blocks only that workflow run
and supplies a retained log; the workflow is not currently confirmed as a
required merge check.

## Rollback

Revert PR #1737 to remove the scheduled step, contract test and updated
repository claims. The existing local `npm run sweep:spacing` instrument is
unchanged and no running environment needs restoration.
