# CC-1738 · Maintain the standalone Zite RLS verifier dependencies

## Summary

The standalone verifier under `zite/docs/execution/rls/api` now has its own
weekly, bounded Dependabot updater. Minor and patch proposals are grouped;
major changes remain separate for review. A source contract fails closed if
the directory, npm ecosystem, cadence, pull-request limit or grouped update
types drift.

This closes only the missing direct-dependency updater slice of TR-15. The
verifier still has no committed resolver lock, so its transitive graph is not
reproducible. Required-check enforcement, authenticated Zite runtime
validation, the Course Engine API resolver lock and broader resolver/egress
work remain open.

## Environments and tenants affected

None. This change can open dependency-update proposals for repository review.
It does not install a package in a running service, publish or activate a Zite
application, deploy code, use institutional data, change credentials or
modify persistent data.

## Risk

Dependabot may open additional pull requests when direct ranges have updates.
The queue is capped at five and minor/patch changes are grouped to keep review
bounded. Because the package remains unlocked, a green proposal is not proof
of reproducible transitive resolution or authenticated runtime behavior.

## Rollback

Revert PR #1738 to remove the updater, source contract and narrowed TR-15
register language. No running environment needs restoration.
