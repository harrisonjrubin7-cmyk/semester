# CC-1729 · Add fail-closed Zite RLS verifier compatibility

## Summary

A dedicated path-filtered workflow builds the standalone Zite RLS verifier's
synthetic schema on disposable PostgreSQL 17, connects its Redis integration
tests, runs the SQL tenant-isolation checks, typechecks the API and executes the
full verifier suite. A repository guard mutation-tests the workflow's database,
Redis, no-lock, SQL, typecheck and executable-test boundaries.

## Environments and tenants affected

None. The workflow uses only committed synthetic fixtures in disposable GitHub
Actions services. It does not deploy or publish Zite, contact an institution,
use institutional data, change credentials, activate a tenant or alter a
persistent database.

## Risk

The verifier's direct manifest versions are exact, but it has no committed
resolver lock and no dedicated recurring updater. Transitive resolution can
therefore change between runs, and open dependency PRs #1695 and #1696 still
need their own review. The gate proves repository compatibility against its
synthetic PostgreSQL/Redis model only. It does not prove the published Zite
runtime, a separately signed-in cross-role journey, production configuration,
provider credentials, accessibility, deployment or institutional acceptance.

## Rollback

Revert PR #1729 to remove the workflow, repository guard and controlled-text
updates. No infrastructure, credentials, tenant data or running service needs
restoration.
