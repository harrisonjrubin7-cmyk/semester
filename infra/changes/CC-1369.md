# CC-1369 · Carry the optional Clerk publishable key into the Pages build

## Summary

The Pages workflow may now pass `VITE_CLERK_PUBLISHABLE_KEY` from the repository
variables or secrets into the product build. When the value is absent, the
deployed app continues to use the existing Supabase-backed account flow.

## Environments and tenants affected

Production Pages builds are affected. Tenants notice no change unless the
publishable key is configured; when configured, the signed-in product receives
Clerk session context while public response and procurement-room links remain
account-free.

## Risk

A malformed or unintended publishable key could make the signed-in application
fail during Clerk initialization. The Pages build, post-deploy smoke checks, and
browser console would expose that within an hour. The key is publishable client
configuration, not a Clerk secret key.

## Rollback

Revert PR #1369 on `main` and let the gated Pages workflow redeploy the prior
commit. This removes the workflow mapping and provider boundary and should take
one normal CI and Pages deployment cycle.
