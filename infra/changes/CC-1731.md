# CC-1731 · Execute the calendar link-token boundary

## Summary

The calendar Edge Function now delegates request handling to an importable
handler. Executable tests reject unsupported methods, missing deployment
configuration and malformed link tokens before database work; preserve the
same response for missing rows and database failures; classify the client into
a fixed family; and verify successful GET and HEAD responses. The trust
register moves this function from an ordered source mutation contract to direct
handler coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, call a published runtime, use institution data,
change credentials, activate a tenant or alter a persistent database.

## Risk

The handler boundary is executed locally, but the hosted function and its
environment are not. Five Edge Functions still rely on ordered source mutation
controls instead of direct handler tests. Required-check enforcement, resolver
and egress locking, authenticated target validation, independent review,
accessibility debt, TR-26 and the Operations Console synthetic/demo boundaries
remain open.

## Rollback

Revert PR #1731 to restore the inline handler and the prior
12-direct/6-source trust-register counts. No infrastructure, credentials,
tenant data or running service needs restoration.
