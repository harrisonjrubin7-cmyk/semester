# CC-1227 · Install the Supply chain job from the workspace root so it can run at all

## Summary

`supply-chain.yml` has failed on every push to `main` since it landed: its
`setup-node` step caches on `app/package-lock.json`, which D-1193 deleted when
the lockfile moved to the repository root, so the job stops before any step
runs. This points the cache at the root `package-lock.json` and runs the
install from the root, as `ci.yml` does. Installing inside `app/` skips the
`@semester/*` workspace links, and the SBOM step would then have failed on
them (`npm sbom`: missing `@semester/contract`, `institution`, `platform`).
The audit, SBOM, build and bundle steps stay in `app/`. **Applies nothing** to
any Terraform root, which is why `Roots` is empty: this record can never
authorise an apply.

## Environments and tenants affected

None. No tenant, deploy or production setting changes when this merges. The
workflow runs only on pushes to `main` that touch its paths, and on manual
dispatch; it has no `pull_request` trigger, so this pull request cannot
exercise it.

## Risk

The attestation steps (build provenance, SBOM attestation, verification) and
the artifact upload have never run on GitHub, because the job has never got
past `setup-node`. The first push to `main` after this merges is their first
run and may fail there; that would be new information, not a regression. It
would show within minutes as a failed Supply chain run on that push. The install
now covers every workspace, so the job is a little slower than an install inside
`app/` alone.

## Rollback

Revert the commit: the workflow returns to its previous state, in which every
push to `main` fails at `setup-node` and nothing is attested. Minutes, no
state to restore. A successful run writes attestations to the repository, and a
revert does not remove those; each describes the build that produced it, which
is accurate for that commit.

## Evidence

- Reproduction on a clean worktree of `main`: with the install inside `app/`,
  `npm sbom` exits `ESBOMPROBLEMS` and the `jq` check fails on an empty file;
  with the install at the root, `npm ci` exit 0 with workspace links, `npm audit
  --omit=dev --audit-level=critical` exit 0, SBOM 140 components and the `jq`
  check passes, `npm run build` exit 0.
- `app/src/lib/workflowpaths.test.ts` fails against `main`'s workflow, naming
  `supply-chain.yml: cache-dependency-path app/package-lock.json`, and passes
  with this change.
- The `policy` check on this pull request passed.
