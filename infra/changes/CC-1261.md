# CC-1261 · Pass one more optional build-time flag through the Pages build

## Summary

Adds `VITE_DOMAIN_TODAY` to `.github/workflows/pages.yml`, in the environment block that
hands the repository's `VITE_*` variables to the build and in the allow-list of names the
build carries forward. It is read by `app/src/lib/experience-flags.ts` and defaults to `off`
when unset, so a build that does not set it is byte-for-byte the build it was before. It
switches on, per build, the domain-backed commitment rows on Today, as described in D-1261.
Nothing else in the workflow changes: no permission, no trigger, no step.

## Environments and tenants affected

None. The variable is not set in any environment, and `off` is the behaviour without it. No
tenant can notice anything when this merges. A build only differs if somebody later sets the
Actions variable to `preview`, `sandbox` or `production`.

## Risk

A typo in the allow-list would drop a name the build should carry, which
`app/src/lib/deploy.test.ts` would fail on before merge. Setting the variable to `production`
changes what that build draws, which is the intended use; the screen falls back to its own
rows whenever the domain's are late, stale or incomplete, and the two are held identical by
`app/src/composition/commitments.test.ts`. A flag that misbehaves is turned off by unsetting
its variable and re-running the workflow.

## Rollback

Revert this pull request's change to `pages.yml` (one line in two places), or, without
touching code, leave the Actions variable unset or set it to `off`. Either takes one Pages
run, a few minutes. Nothing was applied to infrastructure, so there is no state to unwind.

## Evidence

Pull request 1261. `app/src/lib/ops/infrastructure.test.ts` and `app/src/lib/deploy.test.ts`
pass on this branch.
