# CC-1720 · Require Edge Function guard behavior proofs

## Summary

Every deployed Edge Function guard declaration now names a runnable behavior
proof. Eleven functions point to direct handler tests. Seven inline Deno
entrypoints have ordered source contracts with mutation controls that require
the credential refusal to precede protected database or outbound work. The
controlled security register is reconciled with the existing CodeQL workflow
and the current inventory of eighteen functions.

## Environments and tenants affected

None. This change affects candidate tests, source contracts and controlled
repository documents only. It does not deploy an Edge Function, activate a
tenant, alter credentials, connect an institution or use institutional data.

## Risk

The seven inline-entrypoint proofs inspect source order rather than executing the
Deno handlers. The direct proofs and source contracts therefore improve the
repository gate but do not establish authenticated target behavior, complete
security coverage or production readiness. TR-15 remains open for executable
handler coverage, omitted package-tree update automation, and target
testing.

## Rollback

Revert PR #1720 to remove the behavior-proof manifest, inline-entrypoint
contracts and corresponding register reconciliation. No infrastructure state,
credentials or tenant data needs restoration.
