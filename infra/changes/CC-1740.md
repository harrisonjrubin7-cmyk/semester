# CC-1740 · Freeze the Course Engine Python API dependency graph

## Summary

The Course Engine Python API now commits a hashed uv resolver graph. Its
SQLite/PostgreSQL workflow installs and executes that exact graph, checks for
lock drift and builds non-published API and worker candidate images from the
same production dependency set. Source contracts hold the uv version, locked
commands, direct manifest entries, registry hashes and both Dockerfiles.

This closes only the Course Engine API resolver-lock slice of TR-15.
Required-check enforcement, authenticated Zite runtime/LMS validation and
broader resolver/egress locking remain open. PR #1681 also changes the Course
Engine workflow and will need ordinary reconciliation if it lands first.

## Environments and tenants affected

None. The lock, workflow and candidate image builds affect repository
verification only. The workflow does not push an image. This change does not
deploy code, publish a course, activate a tenant, use institutional data,
change credentials or modify persistent production data.

## Risk

A stale lock, unsupported wheel or image-only dependency failure will stop the
candidate. CI fails on lock drift, exercises both SQLite and PostgreSQL and
builds both Dockerfiles before handoff. Existing dependency alerts are not
cleared by this change.

## Rollback

Revert PR #1740 to restore mutable pip resolution and remove the lock
contracts. No running environment needs restoration.
