# CC-1726 · Maintain the root Zite workspace dependencies

## Summary

Dependabot receives a dedicated weekly npm updater for the root `zite/`
workspace manifest and lockfile. Minor and patch updates are grouped, major
updates remain isolated, and repository tests fail if the updater loses its
directory, ecosystem, cadence, pull-request bound or grouped update types.

## Environments and tenants affected

None. This change alters candidate update configuration, tests and controlled
documents only. Zite remains the source of truth for the running apps; this
repository snapshot does not publish or activate them. The change does not
deploy an application, activate a tenant, change credentials, connect an
institution or use institutional data.

## Risk

The updater may open future pull requests against a large workspace lockfile.
The bounded queue, grouped minor/patch changes, isolated major changes,
committed lockfile, advisory scanning and review are the compensating
controls. A clean locked install and audit do not establish executable
compatibility: `zitejs check` currently exits non-zero while bundling the
snapshot endpoints and is not a blocking repository check. The standalone
`zite/docs/execution/rls/api/` verifier has no recurring updater or committed
lockfile. TR-15 also remains open for the seven inline Edge Function handlers
that lack executable behavior tests.

## Rollback

Revert PR #1726 to remove the root Zite updater and its repository guard. No
infrastructure state, credentials, tenant data or running Zite app needs
restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1726
- `app/src/lib/dependencyupdates.test.ts` checks the root Zite workspace
  manifest and lockfile, holds the updater contract and mutation-tests
  directory, ecosystem, cadence, queue bounds and grouped update-type failures.
- Local focused controls: 4 files and 64 tests passed. Full application suite:
  1,603 files and 25,064 tests passed, with 2 files and 81 tests skipped. A
  clean locked root install and the 951-package Zite workspace install both
  reported no vulnerabilities; app lint passed with the existing warning set,
  Dependabot YAML parsing and `git diff --check` passed.
- `zitejs check` is not recorded as passing: after the TypeScript phase began
  successfully it exited non-zero while bundling snapshot endpoints. It remains
  an explicit compatibility gap rather than evidence for this candidate.
- Hosted exact-head CI, CodeQL and HawkScan remain required before handoff.
