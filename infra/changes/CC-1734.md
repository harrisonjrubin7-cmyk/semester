# CC-1734 · Execute the Canvas session boundary

## Summary

The Canvas Edge Function now delegates its user-session boundary to an
importable request wrapper. Executable tests reject missing authorization, a
wrong scheme, an empty bearer, an invalid session and an unreadable session
before protected Canvas egress can run, and prove that only an accepted bearer
session reaches the existing GET-only, public-host, bounded JSON fetch logic.
The trust register moves this function from an ordered source mutation contract
to direct handler coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, call Canvas, use a real Canvas token, call a
published runtime, use institution data, change credentials, activate a tenant
or alter persistent data.

## Risk

The session wrapper is executed locally, but the hosted function, Supabase
environment and authenticated runtime are not. Two Edge Functions still rely
on ordered source mutation controls instead of direct handler tests.
Required-check enforcement, resolver and egress locking, authenticated target
validation, independent review, accessibility debt, TR-26 and the Operations
Console production-evidence boundary remain open.

## Rollback

Revert PR #1734 to restore the inline authentication checks and the prior
15-direct/3-source trust-register counts. No infrastructure, credentials,
tenant data or running service needs restoration.
