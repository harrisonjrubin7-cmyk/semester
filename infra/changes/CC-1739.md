# CC-1739 · Freeze the standalone Zite RLS verifier dependencies

## Summary

The standalone verifier under `zite/docs/execution/rls/api` now commits its
npm resolver graph. Its synthetic PostgreSQL 17 and Redis 7.4 workflow uses
`npm ci` and fails if installation changes the lock. Source contracts hold the
lock format, direct manifest entries, registry integrity records and workflow
install boundary.

This closes only the standalone verifier resolver-lock slice of TR-15.
Required-check enforcement, the Course Engine API resolver lock,
authenticated Zite runtime validation and broader resolver/egress work remain
open. Dependabot PRs #1695 and #1696 change only the verifier manifest and will
need ordinary lock reconciliation before merge.

## Environments and tenants affected

None. The lock and workflow affect repository dependency resolution and
synthetic verification only. They do not publish or activate a Zite
application, deploy code, use institutional data, change credentials or
modify persistent production data.

## Risk

A stale or malformed lock could make the verifier install fail. The workflow
uses the committed graph, checks for lock drift, and then runs type, database,
authorization and limiter verification against disposable PostgreSQL and
Redis services. Existing direct-dependency alerts are not cleared by this
change.

## Rollback

Revert PR #1739 to restore mutable manifest installation and remove the lock
contracts. No running environment needs restoration.
