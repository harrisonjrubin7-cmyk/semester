# CC-1365 · Make the existing workflows pass their new embedded-shell gate

## Summary

The pull request adds actionlint as a CI gate. Its first GitHub run found six
ShellCheck issues in existing workflow scripts: two assignments combined with
`export`, two unused retry counters, and two deliberately split word lists.
The workflows now assign before exporting, name intentionally unused counters
with an underscore, and count the build-input lists with Bash arrays. Commands,
triggers, permissions, secrets, build inputs and deployment destinations do not
change. **Applies nothing** to a Terraform root or hosted environment.

## Environments and tenants affected

None. These edits preserve the existing CI, HawkScan and Pages behavior. No
tenant, deployment, repository setting or infrastructure resource changes when
this merges.

## Risk

Low. A shell rewrite could change an exported value or the count printed in the
Pages build-input notice. The actionlint gate catches syntax and ShellCheck
regressions immediately; the existing CI, HawkScan and Pages workflows exercise
the affected scripts. Any problem is visible in the pull request checks before
merge.

## Rollback

Revert the workflow-lint fix commit. This takes minutes and has no state to
restore, but the developer-tools gate will return to red on the six findings.
The dependency overrides, scanner gate and application code do not need to be
reverted with this record.

## Evidence

- PR #1365's first CI build failed in `./scripts/developer-tools.sh` and named
  all six ShellCheck findings.
- actionlint v1.7.12 with checksum-verified ShellCheck v0.11.0 passes every
  workflow after the edits.
- OSV-Scanner v2.6.0 still reports no unfiltered dependency findings.
- The Infrastructure policy and all three Terraform plan checks passed on the
