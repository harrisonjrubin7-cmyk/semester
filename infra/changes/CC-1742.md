# CC-1742 · Add tablet text-spacing coverage

## Summary

The scheduled WCAG 1.4.12 browser sweep now measures every registered
destination at phone, tablet and desktop widths. Its source contract requires
the 1024-pixel viewport to remain inside the application's tablet tier, and
the runtime rejects malformed or duplicate width configuration before opening
a browser.

This closes only the tablet text-spacing slice of TR-26. Tablet axe coverage,
signed-in, error and modal states, overlap detection, real-device testing and
the manual assistive-technology pass remain open.

## Environments and tenants affected

None. The change affects a scheduled repository browser check and its source
records only. It does not deploy code, publish an artifact, activate a tenant,
use institutional data, change credentials or modify persistent data.

## Risk

The added viewport increases nightly sweep time and can expose a genuine
tablet-only layout regression. A missing destination, page error, malformed
viewport list, failed planted control or newly clipped text makes the sweep
fail rather than silently reducing coverage.

## Rollback

Revert PR #1742 to restore the two-width sweep and its earlier evidence scope.
No running environment needs restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1742
- `app/src/lib/spacingnightly.test.ts` holds the three-tier source contract.
- Local real Chromium sweep opened 189 of 189 destination-width combinations
  with zero page errors and zero new text-loss findings.
- The planted lossy and growing-box controls passed at all three widths.
- Focused local suite: 7 files, 95 tests passed.
- App lint, workflow YAML and `git diff --check` passed.
- Exact-head hosted CI, CodeQL and HawkScan remain required before handoff.
