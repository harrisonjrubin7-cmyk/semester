# CC-1727 · Maintain Course Engine web dependencies

## Summary

Dependabot receives a dedicated weekly npm-ecosystem updater for the Course
Engine web app's package-local pnpm manifest and lockfile. Minor and patch
updates are grouped, major updates remain isolated, and repository tests fail
if the updater loses its directory, ecosystem, cadence, pull-request bound or
grouped update types.

## Environments and tenants affected

None. This change alters candidate update configuration, tests and controlled
documents only. It does not deploy Course Engine, publish a course, activate a
tenant, change credentials, connect an institution or use institutional data.

## Risk

The updater may open future pull requests against the Course Engine web
lockfile. The bounded queue, grouped minor/patch changes, isolated major
changes, committed lockfile, dedicated Course Engine CI and review are the
compensating controls. This slice does not add recurring updates for the
Course Engine Python API, whose `pyproject.toml` declares ranges without a
committed resolver lock. The separate runner-pinning change in PR #1681 also
remains independently reviewable. TR-15 remains open for omitted package
trees and seven inline Edge Function handlers without executable behavior
tests.

## Rollback

Revert PR #1727 to remove the Course Engine web updater and its repository
guard. No infrastructure state, credentials, tenant data, course publication
or running service needs restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1727
- `app/src/lib/dependencyupdates.test.ts` checks the Course Engine web manifest
  and pnpm lockfile, holds the updater contract and mutation-tests directory,
  ecosystem, cadence, queue bounds and grouped update-type failures.
- Local controls passed: 4 focused files and 67 tests; the full application
  suite passed 1,603 files and 25,067 tests, with 2 files and 81 tests skipped;
  app lint passed with the existing warning set; Dependabot YAML parsing and
  `git diff --check` passed; the clean root locked install reported no
  vulnerabilities.
- Course Engine web was installed from the committed lock with pnpm 10.18.3.
  Its 40 unit tests, typecheck, production build and 7 browser acceptance tests
  passed, and `pnpm audit --audit-level high` reported no known vulnerabilities.
- The dedicated Course Engine workflow performs the same lock install, unit
  tests, typecheck, production build and browser checks when Course Engine
  files change. This configuration-only candidate does not itself trigger that
  path-filtered workflow, so local compatibility and hosted repository checks
  remain distinct evidence.
- Hosted exact-head CI, CodeQL and HawkScan remain required before handoff.
