# CC-1743 · Add tablet destination axe coverage

## Summary

The real-browser accessibility smoke now runs axe over every registered
destination at phone and tablet widths. The runtime rejects malformed or
duplicate width configuration, proves the axe instrument with planted
button-name and image-alt violations at each width, and fails when any
destination-width combination is missing.

The first tablet run exposed a shared Decision Trail label-in-name defect on
sixteen destinations. The visible trigger text now includes the same space as
its accessible name, and a clean-server rerun passed every destination at both
widths. Signed-in, error, modal, overlap, laptop and real-device states and the
manual assistive-technology pass remain open.

## Environments and tenants affected

None. The change affects repository application source, automated browser
checks and evidence records. It does not deploy code, publish an artifact,
activate a tenant, use institutional data, change credentials or modify
persistent data.

## Risk

The added viewport increases accessibility-sweep time and can reveal a genuine
tablet-only semantic regression. A missing destination, page error, malformed
width list, failed planted control or serious/critical axe finding makes the
run fail rather than silently reducing coverage.

## Rollback

Revert PR #1743 to restore the phone-only destination axe sweep and earlier
Decision Trail trigger markup. No running environment needs restoration.
