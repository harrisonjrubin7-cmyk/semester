# CC-1725 · Maintain Pipeline dependencies

## Summary

Dependabot receives a dedicated weekly npm updater for the standalone
`pipeline/` manifest and lockfile. Minor and patch updates are grouped, major
updates remain isolated, and repository tests fail if the updater loses its
directory, ecosystem, cadence, pull-request bound or grouped update types.

## Environments and tenants affected

None. This change alters candidate update configuration, tests and controlled
documents only. It does not run the pipeline, generate or publish course
material, deploy an application, activate a tenant, change credentials,
connect an institution or use institutional data.

## Risk

The updater may open future pull requests against the Pipeline dependency
tree. The bounded queue, grouped minor/patch changes, isolated major changes,
committed lockfile and candidate CI are the compensating controls. This
candidate cannot prove a future Dependabot run, generated course output or
deployed service. The broader `zite/` snapshot remains outside update
automation. TR-15 also remains open for the seven inline Edge Function
handlers that lack executable behavior tests.

## Rollback

Revert PR #1725 to remove the Pipeline updater and its repository guard. No
infrastructure state, credential, tenant data or generated course material
needs restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1725
- `app/src/lib/dependencyupdates.test.ts` checks the standalone manifest and
  lockfile, holds the updater contract and mutation-tests directory, ecosystem,
  cadence, queue bounds and grouped update-type failures.
- Local focused controls: 4 files and 61 tests passed. Full application suite:
  1,603 files and 25,061 tests passed, with 2 files and 81 tests skipped. A
  clean locked root install and the standalone Pipeline install both reported
  no vulnerabilities; app lint passed with the existing warning set,
  Dependabot YAML parsing and `git diff --check` passed.
- Hosted exact-head CI, CodeQL and HawkScan remain required before handoff.
