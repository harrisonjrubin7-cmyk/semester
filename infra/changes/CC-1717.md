# CC-1717 · Complete shipped caption inventory

## Summary

Every prerecorded audio file shipped by the candidate tree now has a generated
WebVTT track. The four legacy recordings are recovered from the actual audio,
bound to exact MP3 SHA-256 values, and explicitly labeled machine-generated and
unreviewed. Repository tests fail when a shipped recording lacks a current,
full-length track. This closes the candidate inventory item without raising the
accessibility control above partial or making a conformance claim.

## Environments and tenants affected

None. The change affects candidate source, generated caption files, public
candidate wording and repository tests only. It does not deploy, activate a
service, connect an institution, use real institutional data, change
credentials or modify infrastructure.

## Risk

Machine-generated captions can contain transcription inaccuracies. The hash
and coverage guards prevent missing or stale tracks, but they do not establish
manual accuracy, accessibility conformance, external-video availability or
live-call caption behavior.

## Rollback

Revert PR #1717 to restore the prior caption inventory and candidate wording.
No infrastructure state, credentials or tenant data needs restoration; the
rollback is a source change only.

- `app/src/lib/publicaccessibilityclaims.test.ts` keeps the public candidate
  wording aligned with the evidence boundary.
