# CC-1732 · Execute the push scheduler authentication boundary

## Summary

The push Edge Function now delegates its scheduler authentication to an
importable request wrapper. Executable tests reject missing deployment
configuration, missing authorization, the wrong secret and the wrong scheme
before protected delivery can run, and prove that only the exact configured
bearer secret reaches the existing delivery logic. The trust register moves
this function from an ordered source mutation contract to direct handler
coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, invoke a scheduler, send a notification, use
institution data, change credentials, activate a tenant or alter persistent
data.

## Risk

The authentication wrapper is executed locally, but the hosted function,
scheduler and environment configuration are not. Four Edge Functions still
rely on ordered source mutation controls instead of direct handler tests.
Required-check enforcement, resolver and egress locking, authenticated target
validation, independent review, accessibility debt, TR-26 and the Operations
Console production-evidence boundary remain open.

## Rollback

Revert PR #1732 to restore the inline authentication checks and the prior
13-direct/5-source trust-register counts. No infrastructure, credentials,
tenant data or running service needs restoration.
