# CC-1733 · Execute the fetchcal session boundary

## Summary

The fetchcal Edge Function now delegates its user-session boundary to an
importable request wrapper. Executable tests reject missing authorization, a
wrong scheme, an empty bearer, an invalid session and an unreadable session
before protected calendar egress can run, and prove that only an accepted
bearer session reaches the existing redirect-safe fetch logic. The trust
register moves this function from an ordered source mutation contract to
direct handler coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, fetch a real calendar, call a published runtime,
use institution data, change credentials, activate a tenant or alter
persistent data.

## Risk

The session wrapper is executed locally, but the hosted function, Supabase
environment and authenticated runtime are not. Three Edge Functions still
rely on ordered source mutation controls instead of direct handler tests.
Required-check enforcement, resolver and egress locking, authenticated target
validation, independent review, accessibility debt, TR-26 and the Operations
Console production-evidence boundary remain open.

## Rollback

Revert PR #1733 to restore the inline authentication checks and the prior
14-direct/4-source trust-register counts. No infrastructure, credentials,
tenant data or running service needs restoration.
