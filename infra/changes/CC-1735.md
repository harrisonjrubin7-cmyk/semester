# CC-1735 · Execute the Claude session boundary

## Summary

The Claude Edge Function now delegates its user-session boundary to an
importable request wrapper. Executable tests reject missing authorization, a
wrong scheme, an empty bearer, an invalid session and an unreadable session
before protected generation can run, and prove that only an accepted bearer
session reaches the existing kill-switch, tenant-policy, spend, usage and
provider controls. The trust register moves this function from an ordered
source mutation contract to direct handler coverage.

## Environments and tenants affected

None. The change is repository source and synthetic test coverage only. It
does not deploy the function, call a provider, generate content, use a real
account, call a published runtime, use institution data, change credentials,
activate a tenant or alter persistent data.

## Risk

The session wrapper is executed locally, but the hosted function, Supabase
environment and authenticated runtime are not. The LTI Edge Function still
relies on an ordered source mutation control instead of a direct handler test.
Required-check enforcement, resolver and egress locking, authenticated target
validation, independent review, accessibility debt, TR-26 and the Operations
Console production-evidence boundary remain open.

## Rollback

Revert PR #1735 to restore the inline authentication checks and the prior
16-direct/2-source trust-register counts. No infrastructure, credentials,
tenant data or running service needs restoration.
