# CC-1149 · Pass two optional build-time flags through the Pages build

## Summary

Adds `VITE_DOMAIN_TODAY` and `VITE_DOMAIN_TASKS` to `.github/workflows/pages.yml`,
in the environment block that hands the repository's `VITE_*` variables to the
build and in the allow-list of names the build carries forward. Both are read
by `app/src/lib/experience-flags.ts` and both default to `off` when unset, so a
build that sets neither is byte-for-byte the build it was before. They switch
on, per build, the domain-backed Today list and task ticking described in D-1149.
Nothing else in the workflow changes: no permission, no trigger, no step.

## Environments and tenants affected

None. Neither variable is set in any environment, and `off` is the behaviour
without them. No tenant can notice anything when this merges. A build only
differs if somebody later sets one of the two Actions variables to `production`.

## Risk

Two ways it could go wrong. A typo in the allow-list would drop a name the build
should carry, which `app/src/lib/deploy.test.ts` would fail on before merge. And
setting either variable to `production` changes what that build does, which is
the intended use and is gated on the dogfood week recorded in
`docs/architecture/modular-monolith.md`. Visible within one Pages run; a flag
that misbehaves is turned off by unsetting its variable and re-running the
workflow.

## Rollback

Revert this pull request's change to `pages.yml` (two lines in two places), or,
without touching code, leave the two Actions variables unset or set them to
`off`. Either takes one Pages run, a few minutes. Nothing was applied to
infrastructure, so there is no state to unwind.

## Evidence

Pull request 1149. `app/src/lib/ops/infrastructure.test.ts` and
`app/src/lib/deploy.test.ts` pass on this branch.
