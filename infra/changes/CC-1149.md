# CC-1149 · Pass one optional build-time flag through the Pages build

## Summary

Adds `VITE_DOMAIN_TASKS` to `.github/workflows/pages.yml`, in the environment
block that hands the repository's `VITE_*` variables to the build and in the
allow-list of names the build carries forward. It is read by
`app/src/lib/experience-flags.ts` and defaults to `off` when unset, so a build
that does not set it is byte-for-byte the build it was before. It switches on,
per build, adding, ticking, moving and deleting a task through the tasks domain,
as described in D-1149.
Nothing else in the workflow changes: no permission, no trigger, no step.

## Environments and tenants affected

None. The variable is not set in any environment, and `off` is the behaviour
without it. No tenant can notice anything when this merges. A build only
differs if somebody later sets the Actions variable to `production`.

## Risk

Two ways it could go wrong. A typo in the allow-list would drop a name the build
should carry, which `app/src/lib/deploy.test.ts` would fail on before merge. And
setting the variable to `production` changes what that build does, which is
the intended use and is gated on the dogfood week recorded in D-1149. Visible within one Pages run; a flag
that misbehaves is turned off by unsetting its variable and re-running the
workflow.

## Rollback

Revert this pull request's change to `pages.yml` (one line in two places), or,
without touching code, leave the Actions variable unset or set it to `off`. Either takes one Pages run, a few minutes. Nothing was applied
to infrastructure, so there is no state to unwind.

`app/src/lib/deploy.test.ts` pass on this branch.
