# CC-1746 · Measure the Quick Add storage-refusal state

## Summary

The real-browser accessibility smoke now forces the shared Quick Add modal’s
device-library write to fail on each of the seven critical journeys at 375 and
1024 pixels. It requires a visible alert, preserves the unsaved text, verifies
that no capture was persisted, keeps focus inside the modal, runs serious and
critical axe checks, and verifies Escape focus return. The instrument fails
closed when any of the fourteen journey-width error states is missing.

This is one synthetic local-storage error state. Signed-in, other-error,
additional-modal, other-interactive, real-device and manual assistive-
technology coverage remains open, and the evidence records preserve those
boundaries.

The first exact-head HawkScan also exposed two newly untriaged medium paths for
the inherited `style-src 'unsafe-inline'` fallback. The app now closes that
legacy fallback to `style-src 'self'` while retaining the separately measured
`style-src-attr` and `style-src-elem` allowances required by generated diagrams
in supported CSP3 browsers. Safari before 16.1 is outside the documented latest-
and-previous-major support floor and no longer receives the legacy fallback.

## Environments and tenants affected

The source policy and matching static-host and Vercel header policies change in
the application bundle. This pull request does not itself deploy code, publish
an artifact, activate a tenant, use institutional data, change credentials or
modify persistent data.

## Risk

The added error states increase accessibility-sweep time and can reveal a
journey- or viewport-specific failure in error announcement, state retention,
modal focus or axe results. A missing alert, changed input, unexpected write,
focus escape, page error or serious/critical axe finding fails the run rather
than silently reducing coverage.

Safari before 16.1 will not render the generated inline diagram styling because
it ignores the CSP3-specific directives and now receives the closed fallback.
That browser generation is outside the repository's stated support floor. The
supported CSP3 path keeps the two measured allowances unchanged, so removing
them remains separate migration work rather than an unmeasured hardening claim.

## Rollback

Revert PR #1746 to restore the prior destination and modal-state sweep and the
legacy style fallback. No running environment needs restoration until a later
deployment consumes the change.
