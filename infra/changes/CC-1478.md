# CC-1478 · Add the access policy baseline as policy-as-code, with tests

## Summary

Adds `infra/policy/access.rego` and `infra/policy/access_test.rego`: the eight
conditions every allowance must satisfy, written once in the order the platform
evaluator checks them, with a `deny` set that names the failed condition. Nothing
about production changes afterwards. The policy is evaluated by `opa test` in CI;
the gateway's runtime evaluator (`packages/platform/src/policy/engine.ts`) is not
changed and does not load this file.

## Environments and tenants affected

None. No root applies these files, and no tenant's requests, headers, limits or
access decisions change. This record is blank in `Roots` for that reason.

## Risk

The policy could drift from the runtime evaluator without anyone noticing, which
would make the baseline look stronger than it is. That is detected by the policy
tests and the runtime evaluator's own tests, not by production traffic. The
mitigation is that the file's header says what it is not.

## Rollback

Revert the commit that adds the two files (`git revert` of the commit introducing
`infra/policy/`). It has no runtime effect, so the revert takes a few minutes and
needs no data step.

Filled in on `applied`. Until then: the `opa test infra/policy` result from the
pull request's `policy` check.
