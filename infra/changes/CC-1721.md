# CC-1721 · Maintain Edge Function dependencies

## Summary

Each of the eighteen deployed Edge Functions receives an isolated `deno.json`
manifest and integrity lock. Registry versions move out of TypeScript import
specifiers and into those manifests, and Dependabot is configured to update them weekly with
cross-function grouping by dependency name. Repository tests fail if a
function loses its manifest, a registry version returns to source, or the Deno
updater is removed.

## Environments and tenants affected

None. This change alters candidate source, dependency manifests, update
configuration, tests and controlled documents only. It does not deploy an Edge
Function, activate a tenant, change credentials, connect an institution or use
institutional data.

## Risk

Manifest aliases must resolve identically when Supabase bundles each function.
The candidate suite and hosted checks can validate repository behavior, but do
not prove a deployed function, authenticated target, production configuration
or future Dependabot pull request. Video, pipeline and workflow-lab update
automation also remains open under TR-15.

## Rollback

Revert PR #1721 to restore the registry-qualified TypeScript imports and remove
the function-local manifests and Deno updater. No infrastructure state,
credential or tenant data needs restoration.

## Evidence

- Pull request: https://github.com/harrisonjrubin7-cmyk/semester/pull/1721
- `app/src/lib/denodependencies.test.ts` inventories all eighteen manifest/lock
  pairs, forbids registry-qualified imports in source and mutation-checks the updater.
- `app/src/lib/supplychain.test.ts` holds the Deno ecosystem and manifest glob
  alongside the existing npm and Actions update paths.
- Hosted exact-head CI, CodeQL and HawkScan remain required before handoff.
