## How to read the table

- **In CI?** answers only "does a workflow run it on a pull request or on main". `Yes (build)` means `.github/workflows/ci.yml` job `build`, step `Test` (`npm test`, `app/package.json` script `test`) or step `Check the database policies` (`supabase/check.sh`, which iterates every `supabase/*.check.sql`: `supabase/check.sh:52`). No check below is a *required* GitHub status check today: `gh api repos/harrisonjrubin7-cmyk/semester/rules/branches/main` returned `[]` and `.../rulesets` returned `[]` on 2026-10-04, matching the empty "Applied" table in `docs/BRANCH-PROTECTION.md`. So "in CI" means "runs and reports", not "blocks merge".
- **Phase**: `Phase 1` = would be a gate before any pilot; `Phase 2` = before multi-school activation; `Phase 3` = maturity. These are proposals for the owner, not decisions.
- A passing in-repo check is evidence about the named tree only; it is not evidence about the deployed system.
