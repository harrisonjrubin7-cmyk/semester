# Complete all 122 through connected loops
## Rule
This package completes source-derived specification coverage and local review tooling, not all production implementations. Reuse the canonical repository capability registry, role grants, release evaluator and migrations. The design project mainframe instructions require complete tested journeys and explicitly forbid treating reference migrations as production installation instructions.

## Step 0 — immutable reconciliation
Read repository instructions, current diff and handoff. Freeze SHA; inventory routes, grants, actual migrations, server commands, workers and tests. Map each source key to a canonical key or alias. Record objects in DESIGN-CATALOG-GAPS without declaring them absent from the live repository. Separate build prerequisites from runtime collaborations; the latter may be cyclic by design.

## Step 1 — foundation, not bootstrap duplication
Map shared identity/membership/grants/audit first. Implement object policy and scoped command binding, current-state rechecks and durable receipt/outbox in existing systems. Validate revocation, expiry, stale version, tenant isolation, replay and concurrent commands. Never use the lab's synthetic owner check as institution authorization: faculty, registrar and staff policies require explicit role/object scope decisions.

## Step 2 — public-to-app journey
Approved company/product/solution content → scoped demo/quote lead → approved follow-up → signup → single-use handoff → role-authorized first action. Public forms require abuse protection, input validation, consent, suppression, retention and actual authorized delivery adapters. No email, booking or CRM write was sent by this package.

## Step 3 — student/faculty learning
Course membership → accessible published content → assignment/rubric/AI rule → private drafting → durable submission → reviewed grading → controlled release → Today/inbox notification. Cover assessment attempt limits, accommodations, timezone handling and source-aware study tools.

## Step 4 — registration/institution loop
Institution approved source → academic catalog/term/section → readiness evidence → student action → office handoff → reviewed exception → owning authority confirmation → reconciliation → current projection. Unknown stays unknown; enrollment remains source-owned.

## Step 5 — privacy/support/family
Category consent → scoped delegation or support window → access → expiry/revoke → cache/search/session propagation → export/deletion/offboarding with lawful exception handling. Link edu.support_access to ops.support_session; do not invent universal support impersonation.

## Step 6 — campus/career/housing/community
Service intake, wellbeing access, career artifacts, housing application/maintenance and governed marketplace work each get office/source ownership, safety, accessible fallback, disclosure rules, audit and recovery. Official room assignment is distinct from application acceptance.

## Step 7 — commercial/company/customer
Quote → approved contract → implementation → gated activation → customer support/adoption → measured renewal. Subscription → invoice → regulated rail → authenticated provider event → balanced ledger → settlement reconciliation → approved refund reversal. Keep customer commercial records distinct from student-account balances and institution billing.

## Step 8 — platform operations/developer
Release evidence → exact-target two-person activation; configuration/reliability/jobs/connectors/database/recovery/security/privacy/AI/cost/moderation queues use least privilege. Developer apps/keys/sandbox are scoped, revocable and synthetic by default. Replay a dead letter only after current authority and deduplication checks.

## Activation gates
Code and schema reconciliation; exact SHA CI; negative tenant/object tests; current policy/consent/approval; source/projection freshness; supported failure states; qualified accessibility/security review; legal/commercial/customer scope; staffed incident/support; witnessed restore/rollback/rights/offboarding; accepted UAT and stop criteria. Evidence binds target, tenant, environment, cohort and data mode and expires by policy. Local checklists never authorize launch.

## Agent handoff
Select one dependency-ready complete-loop increment from IMPLEMENTATION-BACKLOG. Inspect existing files before writing. Add negative authorization, concurrency and failure tests; run verified repository checks; retain exact outputs. Update canonical evidence and handoff. Stop before remote push/deployment/migration/messages/financial or academic actions without specific approval.
