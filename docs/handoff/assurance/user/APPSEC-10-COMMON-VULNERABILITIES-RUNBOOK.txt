1. Classify and contain. If access to another student's/institution's data is plausible, disable
the narrow route/grant or revoke the exposed credential first; preserve evidence.
2. Capture safely. Record UTC timestamps, role/tenant, correlation ID, commit/deploy,
migration/config version, expected/actual behavior, and sanitized proof. Never copy raw
tokens, student records, or production secrets into tickets or chat.
3. Reproduce with synthetic fixtures. Model two users and two tenants. Test UI, direct API,
RPC, exports, storage, realtime, cache, and background-job paths—not just the screen
where it was noticed.
4. Trace trusted boundaries. Browser -> API -> validated identity -> tenant/capability decision
-> DB/RLS or privileged worker -> output/log/audit event.
5. Fix cause and siblings. Search equivalent routes, functions, views, policies, and data
copies. A client-side hide, a new UI condition, or a WAF rule is not a complete authorization
fix.
6. Retest independently. Re-run original and sibling negative tests, positive authorized
behavior, fresh/upgraded database migrations, and monitor aer deployment.
Debug flow
Potential unauthorized education-record access, active secret exposure, privilege escalation, or
cross-tenant access is a release blocker. Assign an incident commander; preserve evidence;
assess scope; rotate/revoke where relevant; involve privacy/legal for contractual and legal-
notice decisions. Internal remediation targets are proposed only: critical contain
immediately/fix within 24 hours where feasible; high within 7 days; medium 30; low 90.
