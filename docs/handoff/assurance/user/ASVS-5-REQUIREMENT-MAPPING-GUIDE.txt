Replace the prior chapter-only mapping with a version-pinned, requirement-level control
matrix. ASVS 5.0.0 has 345 requirements across 17 chapters. Do not derive IDs/text from old
4.0.3 documents, summaries, or an LLM; obtain the official 5.0.0 release artifact and preserve it
with a hash and retrieval date.
1. Freeze scope: commit, apps/services, environments, data classes, API types, integrations,
and planned ASVS level. Record exclusions and rationale.
2. Acquire the official ASVS 5.0.0 source from OWASP, retain the release/tag reference and
SHA-256 of the downloaded source. Capture official requirement ID, title/text, level,
chapter, and applicability fields in a controlled CSV.
3. Import requirements into asvs-5-requirement-matrix.csv with columns:
asvs_version,asvs_id,chapter,requirement_text,level,applicable,applicability_ratio
nale,asset_or_feature,control_id,implementation_ref,test_id,test_type,evidence_uri
,status,owner,reviewer,last_verified,next_review,exception_id,notes.
4. Decide applicability one requirement at a time. “Not using WebRTC,” for example, can
make V17 requirements N/A, but only aer architecture confirmation. OAuth/OIDC,
GraphQL, WebSockets, uploads, payments, and AI require feature-based scoping; do not
mark whole chapters N/A casually.
5. Link each applicable ASVS requirement to one or more Semester controls, implementation
references, and test cases. One control can satisfy multiple requirements, but each
requirement needs its own evidence/decision record.
6. Test independently: source/configuration inspection, automated test, manual behavior
test, and operational evidence where relevant. Record exact environment, commit/deploy,
test identity/role, expected/actual result, artifact hash, and tester.
7. Have security review PASS, FAIL, N/A, and exception decisions. Exceptions need risk
owner, compensating control, expiry, and retest date. A merged ticket does not prove a
requirement is met.
8. Produce chapter rollups only from rows: applicable PASS / applicable total; report FAIL,
unverified, N/A, and exception counts separately. Never call a partially scoped spreadsheet
“ASVS compliant.”
