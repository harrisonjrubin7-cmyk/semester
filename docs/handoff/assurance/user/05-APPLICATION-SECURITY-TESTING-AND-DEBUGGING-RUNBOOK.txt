1. Secret scanning: current tree, relevant Git history, bundles, source maps, docs, CI output,
and artifacts. Candidate tools: Gitleaks or equivalent. Treat suppressions as reviewed
exceptions, not broad allowlists.
2. Dependency/SCA: inspect lockfiles and transitive dependencies with supported package
tooling or a maintained scanner; record runtime/dev/build scope, exploitability,
reachability, and advisory version. Generate an SBOM when supported.
3. SAST: use maintained TypeScript/JavaScript and SQL rules (for example Semgrep/CodeQL
as applicable). Review unsafe HTML, injections, authorization gaps, SSRF paths, unsafe
redirects, secrets, and dangerous shell/process usage.
4. Configuration/IaC: inspect CI permissions, deployment exposure, environment separation,
headers/CORS, storage access, database grants/policies, and integration scopes.
5. Authenticated staging DAST: use an approved scanner such as OWASP ZAP with separate
role contexts. Exclude destructive operations unless explicitly approved. Verify
authentication remains active during the scan; unauthenticated coverage is not
authenticated coverage.
6. Manually validate findings, deduplicate, record false-positive rationale, and compare scan
coverage to the asset inventory.

1. Classify: routine defect or possible security incident. Contain credible active exposure
before deep diagnosis.
2. Capture minimal sanitized evidence: correlation ID, UTC times, role/tenant,
commit/deploy, config/migration version, expected/actual result.
3. Preserve evidence access-controlled; never paste production records, tokens, keys, or raw
auth headers into tickets/chat/AI prompts.
4. Reproduce with synthetic fixtures in isolated staging. Avoid attaching debuggers or
verbose sensitive logs to production without explicit operational approval.
5. Trace layers: UI -> gateway/API -> validated identity -> capability/tenant -> DB policy/RPC ->
integration/job -> audit event.
6. Identify root cause, equivalent vulnerable paths, timing/race behavior, and impact; do not
stop at symptom suppression.
7. Implement smallest safe change, add regression test, review independently, run full
affected suite and verify rollback/migration compatibility.
8. Deploy with approval, verify authorized and denied paths, monitor, then remove
temporary diagnostics.
