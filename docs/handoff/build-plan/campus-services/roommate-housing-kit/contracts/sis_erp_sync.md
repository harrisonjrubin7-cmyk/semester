# Legacy SIS / housing / ERP integration contract
PROPOSED; vendor endpoints/scopes/protocols not verified. No live connectors changed.

Authentication: institution SSO for people; approved machine identity (OAuth client credentials, mTLS or institution-approved equivalent) for services; private vault refs and rotation. No admin keys in browser. Tenant/actor derived server-side. Actual protocol and rate limits taken from accepted vendor API contract, never guessed.
Transport preferences: documented API with cursor/version and authenticated events; supported signed webhooks plus pull reconciliation; approved CDC where vendor permits; encrypted SFTP batches only when required, with manifest/checksum/signature and sequence. Do not scrape portals or bypass licensing.

Envelope: event_id, source_system, source_entity/source_id, institution, operation, mapping/schema version, effective_at, observed_at, source_version or monotonic sequence, correlation, data classification, payload reference/digest, tombstone semantics. Timestamps alone are not ordering; source version is opaque unless vendor defines ordering. Canonical IDs resolved from immutable scoped mappings.
Flow: validate auth/schema/scope -> durable inbox/dedupe -> normalize -> source-authority and policy evaluation -> transactional apply/audit/outbox -> durable processing receipt -> checkpoint. Network delivery acknowledgement differs from applied/reconciled business receipt. Repeated same event digest returns prior result; changed digest for same event quarantined. Version gaps and deletions require explicit source reconciliation.

Write contract: exact preview, expected source/object version, scoped idempotency key and payload digest, permitted operation, current approvals. Provider timeout => unknown, not failed. Query source before replay. One authoritative writer per field/domain. Semester outbox success never means ERP/SIS accepted.
Reconciliation: identity/inventory/occupancy/contracts/groups/charges/credits/open tickets/files/access references. Counts + field-level semantics + checksums + exception ownership; no silent last-write-wins on assignments or finances. Daily cadence/freshness/latency/RTO/RPO are customer-defined activation values, not invented promises.
Failure states: healthy; degraded-read (only policy-permitted labelled stale view); writes-held; source-gap; quarantined; outcome-unknown; recovering; reconciled. Old source cannot become authoritative automatically. Failover availability is not permission. Keep drafts, receipts and queued work. Funds/bed/credential changes held when essential authority unavailable.
Cutover: pin field-authority map and migration manifest; rehearsal -> approved parallel comparison -> customer UAT -> freeze/checkpoint -> signed authority change -> monitored verify -> retirement. Rollback may require forward repair/reconciliation of already committed native writes; no stale legacy overwrite.
Acceptance: forbidden tenant/forged service denied; out-of-order/duplicate/gap handling; cancelled enrollment; conflicting bed; missing signature/attachment; uncertain payment; ERP charge replay; credential revoke; restore plus current revocations. Runtime adapter tests NOT RUN.
