# Student experience — connected workflow
Source basis: docs/master/SEMESTER_WORKFLOW_CATALOG.md describes a 40-step design-level student journey; docs/native-platform/NATIVE_WORKFLOW_CATALOG.md describes the daily loop. Capability crosswalks in this package are proposed because these catalogs use different key namespaces.

## Entry to first value
Public role page → account/SSO → verified institution relationship → role grants → privacy and AI choices → approved course/source context → Today → first meaningful action → durable confirmation.
Declining optional AI or integrations must leave permitted native private work available. No static-site button authenticates or claims a preview without the canonical identity/handoff service.

## Daily loop
Open → see current situation → understand priority → take action → source-aware guidance → confirmation → progress → return with clarity.
Today, Plan, Learn, Search and Inbox share canonical objects; do not create separate assignment copies. Student-controlled executive-function help remains optional and reversible.

## Learning
Published assignment/rubric/course AI rules → private draft → approved-source study → submission → immutable receipt → reviewed feedback → released grade. Graded is not released. AI suggestion is not official feedback until reviewed. What-if planning is private and not an official grade.

## Registration
Plan → compare sections → readiness as of identified sources → missing/stale/confirmed blockers → owning-office handoff → approved resolution → reconciliation → updated view. Owning institution system confirms registration. One cleared hold does not imply ready; ready does not imply enrolled.

## Support and campus
Ask/find approved support → minimum context → responsible office → acknowledged handoff → follow-up → student confirmation. Career, services, community and housing stay linked to the same account and permissions, not hidden independent portals.

## Sharing and rights
Student chooses audience/category/expiry → grant receipt → access history → revoke/expire → enforcement verification. Support sessions and family accounts never imply broad access. Export/deletion/correction follow identity, retention and lawful-exception controls. Alumni transition changes grants without confusing academic authority or erasing required records.
