# SEM-17 — Marketplace governed by same consent

Status: Proposed build specification, 2026-10-08. Not a verified implementation, test result, deployment, certification or approved commitment.

## Accountable roles and dependencies
Proposed owner: Marketplace + trust + partner operations. Actual owner is unassigned.
Dependencies: Developer installs, shared grants, moderation, commerce controls.

## Requirements
Listings expose provider, functions, exact data scopes, regions, retention, support, price terms if applicable and evidence badge limits. No marketplace-specific bypass of permission model. Review user content, fraud, accessibility, disputes and payments through authorized processors.

## Workflow
Submit listing → review → publish scoped claims → compare/preview install → tenant and student approvals → monitor → revoke/delist/offboard.

## Acceptance tests
Paid app gets no extra record rights; app update cannot expand access silently; delisted app access follows incident/offboarding policy; reviews reveal no private academic records.

## Metrics to define and measure
scope comprehension; unauthorized grants; complaint resolution; partner review expiry; exit completeness. Define eligible population, numerator/denominator, observation window, source, exclusions, uncertainty and owner before reporting. No achieved values or universal targets are asserted.

## Activation boundary
Revenue-sharing rates and commercial promises remain unapproved unless expressly contracted; existing planning figures are not adopted here.

All relevant tenant isolation, privacy, source-authority, accessibility, monitoring/support, audit, recovery and institutional authorization gates remain mandatory. Evidence attaches to exact artifact/configuration and tenant/domain scope. Unresolved critical isolation, prohibited egress, unauthorized-action or official-integrity defects block activation.
