# SEM-01 — Daily student workspace

Status: Proposed build specification, 2026-10-08. Not a verified implementation, test result, deployment, certification or approved commitment.

## Accountable roles and dependencies
Proposed owner: Product + student experience engineering. Actual owner is unassigned.
Dependencies: Identity, graph, Action Center, search, workspace, design system.

## Requirements
Unify today/this week, deadlines, registration readiness, course work, study, support and career evidence. Persist context between domains. Students control priorities, reminders and private work; no forced AI or duplicate calendars.

## Workflow
Open Today → reconcile sourced obligations → student selects next action → complete in native workspace or authorized integration → confirm outcome → update shared Action Center.

## Acceptance tests
Two course sources generate one task by origin key; a course assignment links to study and advising without another identity; offline work stays draft; compare preferred daily use with the declared cohort's baseline tool stack.

## Metrics to define and measure
journey completion; repeat-use retention; self-reported tool switching; missed-task recovery; accessibility barriers. Define eligible population, numerator/denominator, observation window, source, exclusions, uncertainty and owner before reporting. No achieved values or universal targets are asserted.

## Activation boundary
Daily preference is an adoption hypothesis, not inferred from screen count. Activate only after critical journeys, sharing boundaries and six-state accessibility pass.

All relevant tenant isolation, privacy, source-authority, accessibility, monitoring/support, audit, recovery and institutional authorization gates remain mandatory. Evidence attaches to exact artifact/configuration and tenant/domain scope. Unresolved critical isolation, prohibited egress, unauthorized-action or official-integrity defects block activation.
