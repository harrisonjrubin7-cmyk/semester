With RLS enabled and no applicable policy, PostgreSQL uses default deny: ordinary queries
cannot see or modify rows. Table privileges and RLS are separate layers.
Use:
Table privilege
AND
At least one applicable permissive policy
AND
Every applicable restrictive policy
Permissive policies combine with OR; restrictive policies combine with AND. Adding a
permissive “deny” policy does not override another permissive allow policy.
The following is a template, not directly runnable. It assumes:
A nonprivileged semester_runtime database role.
Trusted identity-resolution functions.
A reviewed scope-checking function.

export function buildLtiAudit(
evidence: ValidationEvidence,
) {
const required: LtiCheck[] = [
"signature",
"issuer",
"audience",
"authorized_party",
"time_window",
"state",
"nonce",
"browser_binding",
"deployment",
"message_type",
"version",
"target_uri",
"resource_link",
"roles_shape",
"roles_vocabulary",
"subject",
"replay",
];
const failed = Object.entries(evidence.checks)
.filter(([, result]) => result === "fail")
.map(([check]) => check);
const incomplete = required.filter(
check => evidence.checks[check] !== "pass",
);
// Identified resource-link handler.
const accepted =
failed.length === 0 &&
incomplete.length === 0 &&
evidence.trustedTenantId !== undefined &&
evidence.deploymentId !== undefined;
return {
eventType: "lti.resource_launch.validation",
attemptId: evidence.attemptId,
requestId: evidence.requestId,
tenantId: evidence.trustedTenantId ?? null,
registrationId: evidence.registrationId ?? null,
deploymentId: evidence.deploymentId ?? null,
outcome: accepted ? "allow" : "deny",
failureCode: evidence.failureCode ?? null,
checks: evidence.checks,
failedChecks: failed,
incompleteChecks: incomplete,
subjectTokenId: evidence.subjectTokenId ?? null,
sectionId: evidence.localSectionId ?? null,
resourceId: evidence.localResourceId ?? null,
mappedPermissions: [...evidence.mappedPermissions],
authorizedPermissions: [
...evidence.authorizedPermissions,
],
customKeys: [...evidence.recognizedCustomKeys],
};
}

This prevents the two database workflows from independently deciding that the other is
absent.
If intake occurs through external email, paper, or another university system, provide an
immediate preservation process and synchronization path. Database locking cannot protect
against a request the institution received but has not recorded.
Required disclosure records remain as long as the studentʼs education records are
maintained.
Education records cannot be destroyed while an inspection/review request is outstanding.
Inspection responses are due within a reasonable period, no more than 45 days aer
receipt.
Recordkeeping exceptions must be classified separately from operational access logging.
Do not activate automated disposition until tests prove:
Missing, expired, or unapproved review rejects deletion.
Records-retained and hold states reject deletion.
