CREATE FUNCTION semester.housing_allocation_version()
RETURNS trigger
LANGUAGE plpgsql
SET search_path = pg_catalog
AS $$
BEGIN
IF NEW.tenant_id IS DISTINCT FROM OLD.tenant_id THEN
RAISE EXCEPTION 'Allocation tenant cannot change'
USING ERRCODE = '23514';
END IF;
NEW.created_at := OLD.created_at;
NEW.updated_at := clock_timestamp();
NEW.version := OLD.version + 1;

END;

The occupancy interval is [start, end): one assignment can end exactly when another begins.
Reservations and assignments share the same allocation boundary.
The DDL does not implement eligibility, selection windows, state-transition authority, or
expiration workers. Those remain server-command responsibilities.
The housing migration enables and forces RLS without adding policies. Ordinary users cannot
see or modify rows.
PostgreSQL uses default deny when RLS is enabled and no applicable policy exists. Table
privileges remain a separate requirement.

This reference gives housing staff institution-wide read scope. Building, cycle, team, or case
restrictions require additional relationships.
Permissive policies combine with OR; restrictive policies combine with AND. The restrictive
tenant policy therefore remains a boundary around the permitted reads.
The helper functions look up session_user in an administrator-managed binding table. They do
not trust a client-set tenant variable.
That works for the dedicated-session reference model. Before using Supabase or a pooled API,
replace it with a verified session/JWT identity resolver and run equivalent behavioral tests.
No direct INSERT, UPDATE, DELETE, or TRUNCATE privileges are granted to the reader. PostgreSQL
RLS does not govern TRUNCATE, and superusers or BYPASSRLS roles remain privileged.
The suite uses populated university A/B fixtures rather than relying only on empty tables.

This illustration uses placeholders; the attached suite contains concrete UUID fixtures.
throws_ok checks the SQLSTATE, while is checks row counts and lives_ok checks that valid
operations succeed. Using NULL for expected error text avoids dependence on localized
PostgreSQL messages.

The 16 cases cover valid launch, issuer, audience, nonce, deployment, target, resource, ASCII
subject, malformed/empty roles, expiration, signature, replay simulation, authorized party,
mentor scope, and unknown contextual claims.
One correction to an earlier response: LTI permits an empty roles array. If the array is
nonempty, it must contain at least one role from the defined vocabularies. The package allows
the empty-array case.
The checker implements a documented role-vocabulary subset. Extend the full vocabulary and
perform real LMS, browser-state, key-rotation, and atomic replay tests before claiming
interoperability.

Required dependencies include PostgreSQL, btree_gist, pgTAP, pg_prove, Node.js, and the npm

The dashboard is a functional local test runner, not yet a production governance monitor.

evidence, live audit/sync sources, institutional retention controls, and independent security
