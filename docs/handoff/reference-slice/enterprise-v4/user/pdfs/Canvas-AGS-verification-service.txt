1. ags.mjs score synchronization
Client responsibilities
syncOnce(repository, client, job) follows this sequence:
1. Acquire the jobʼs academic sequencing locks.
2. Check whether a newer grade revision supersedes it.
3. Reuse the stored line-item binding.
4. If no binding exists, discover matching columns.
5. Stop if multiple columns match.
6. Before creating, persist a creation intent.
7. Save the confirmed column binding.
8. Post the exact approved score event.
9. Record Delivered.
10. Read results when authorized.
11. Compare normalized values and record Verified, Conflict, or VerificationPending.
The comparison accepts equivalent denominators:
Math.abs(
result.resultScore / resultMaximum -
payload.scoreGiven / payload.scoreMaximum
) <= 1e-6
A result observation is different from a successful score request. Preserve that distinction in
the dashboard.

The extension batches local jobs—not one bulk AGS request.
await dispatchBatch(jobs, deliver, {
concurrency: 4,
keyOf: job => job.laneKey
});
It processes separate lanes concurrently, orders revisions within a lane, and blocks later work
aer an unresolved predecessor. A suitable lane includes tenant, deployment, line item, and
LTI user.
This local sequencing still needs distributed database ownership. PostgreSQL FOR UPDATE SKIP
LOCKED supports competing queue consumers, but a row claim alone does not implement
revision ordering or lease recovery.

2. service.mjs HTTP verification
Request flow
Existing protections
Verification errors return a generic rejection.
Successful responses omit the full private JWT payload.
Responses use Cache-Control: no-store.
For /verify, the trusted application supplies:
{
"token": "<id_token>",
"state": "<callback-state>",
"browserBinding": "<trusted-gateway-binding>"
}
The binding must come from the gatewayʼs established browser correlation. A public client
must not choose an arbitrary binding and thereby authenticate itself.
Set explicit server timeouts:
server.headersTimeout = 10_000;
server.requestTimeout = 15_000;
server.keepAliveTimeout = 5_000;
server.maxHeadersCount = 50;
These are proposed values to tune against your proxy configuration. Node documents header
and whole-request timeouts as protections against incomplete or slow requests.

The current cache has a deliberate limitation: it does not immediately refresh on an unknown
kid. A newly rotated key can therefore fail until cache expiration.
For production, add controlled unknown-key refresh with:
Concurrent-refresh deduplication.
A refresh cooldown.
One verification retry.
Fail-closed behavior.
Tested overlap during key rotation.
Avoid a refresh on every invalid signature; that lets malicious tokens generate outbound traffic.
The verifier:
Accepts only compact RS256 tokens.
Selects keys only from trusted registration JWKS.
Requires exactly one compatible key matching kid.
Rejects private key material.
Rejects unsupported critical headers.
Requires the proposed minimum RSA key size.
Verifies the original encoded header/payload bytes.
It never trusts a token-supplied key URL or embedded key.

4. Queue and audit architecture
Distinguish two guarantees:
Local idempotency: repeated enqueue of the same approved revision produces one intent.
Remote reconciliation: determine what the LMS currently contains aer an uncertain
request.
Do not claim exactly-once remote delivery.
The enqueue transaction should atomically create the grade-publication event, sync job, and
audit record. A duplicate idempotency key must also match the stored payload hash; changed
content is not the same intent.
Claim a lane and its next job atomically.
Commit the claim before HTTP.
Renew ownership while processing.
Require owner/fence checks on local completion writes.
Reconcile expired Delivering jobs before sending again.
Never assume a local fencing token cancels an already-sent LMS request.
PostgreSQL advisory locks are cooperative application locks; they are not automatically
enforced against all writers.
Record tenant, job, approved revision, correlation ID, transition, HTTP status, and sanitized
reason code.
Do not log bearer tokens, private keys, full JWTs, student feedback, or complete grade payloads.
