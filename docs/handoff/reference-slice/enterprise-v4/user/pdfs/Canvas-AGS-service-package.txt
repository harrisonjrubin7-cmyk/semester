2. PostgreSQL queue schema
enqueue():
1. Creates the lane if necessary.
2. Canonically serializes and hashes the approved payload.
3. Inserts the event with a tenant-scoped unique key.
4. Returns the existing job for an identical repeated request.
5. Rejects the same key with different payload, lane, or revision.
6. Writes an enqueue audit record transactionally.
This is local idempotency—not exactly-once LMS delivery.
The worker locks an eligible lane:
SELECT l.*
FROM ags_lanes l
WHERE l.tenant_id = $1
AND l.blocked_reason IS NULL
AND (
l.owner IS NULL OR l.lease_until < now()
)
AND EXISTS (
SELECT 1
FROM ags_jobs j
WHERE j.tenant_id = l.tenant_id
AND j.lane_key = l.lane_key
AND j.state IN ('Queued', 'RetryScheduled')
AND j.due_at <= now()
AND NOT EXISTS (
SELECT 1
FROM ags_jobs p
WHERE p.tenant_id = j.tenant_id
AND p.lane_key = j.lane_key
AND p.revision < j.revision
AND p.state NOT IN (
'Verified', 'DeliveredUnverified'
)
)
)
ORDER BY l.lane_key
FOR UPDATE OF l SKIP LOCKED
LIMIT 1;
PostgreSQL explicitly identifies SKIP LOCKED as useful for queue-like consumers, while warning
that it produces an inconsistent view unsuitable for ordinary queries.
The transaction then assigns an owner, lease, and incremented fence; marks the job delivering;
and records the claim. It commits before HTTP.

export async function runWorker(
queue,
deliver,
{ signal }
) {
while (!signal.aborted) {
const job = await queue.claim();
if (!job) return;
let outcome;
try {
outcome = await deliver(job);
} catch (error) {
outcome = failureOutcome(
error,
job.attempts
);
}
await queue.finish(job, outcome);
}
}
The deliver() callback connects to the previous AGS client. It must return Verified or
DeliveredUnverified only aer the corresponding checks.
Outcome Handling
HTTP 429 Bounded retry with jitter and Retry-After
Eighth rate-limit attempt Dead letter
Write timeout or 5xx Outcome unknown; block lane for reconciliation
Other rejection Action required; block lane
Result mismatch Conflict; block subsequent revisions
Expired unresolved delivery Block for recovery—not blind redelivery
The queue handles already-bound score jobs. Line-item creation still requires the separate
durable creation-intent/reconciliation workflow from the earlier implementation.
3. Retry loop and recovery
Implemented loop
Failure policy
No lease heartbeat is included.
Expired deliveries require an audited reconciler.
Credential invalidation/renewal aer 401 is not automated.
The scheduler must poll again aer an empty claim.
Publication and enqueue need integration into one application transaction; this enqueue()
opens its own transaction.
Local fencing cannot cancel an LMS request already transmitted.
These are release blockers, not optional polish.
