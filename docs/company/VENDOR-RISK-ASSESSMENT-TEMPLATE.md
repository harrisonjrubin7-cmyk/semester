## Purpose

Document a scope-specific decision to approve, condition, reject, or replace a vendor. Evidence must reflect Semester's actual intended configuration and data/access—not generic reputation.

## Assessment

| Domain | Evidence/questions | Rating | Gap/condition | Owner/due |
| --- | --- | --- | --- | --- |
| Business/financial | need, alternatives, viability, concentration, cost/renewal |  |  |  |
| Legal/IP | entity, terms, confidentiality, ownership, licenses, liability, disputes |  |  |  |
| Privacy/data | roles, purpose, minimization, training/ads, retention/deletion, rights, regions/subprocessors |  |  |  |
| Security | assurance scope/date, access/MFA, encryption config, logging, vulnerability/incident, SDLC |  |  |  |
| Reliability/continuity | availability evidence, backup/recovery, support, exit/portability |  |  |  |
| Accessibility | product evidence, testing, roadmap, support for barriers |  |  |  |
| AI | model/provider, prompts/data, training, human oversight, safety, kill switch/change notice |  |  |  |
| Implementation/operations | owner, configuration, monitoring, support, offboarding test |  |  |  |

Ratings: **LOW**, **MODERATE**, **HIGH**, **CRITICAL**, or **UNKNOWN**. Unknown material facts increase risk; they are not assumed favorable.

## Decision

`APPROVE | APPROVE WITH CONDITIONS | REJECT | REPLACE | DEFER`

Record approvers, evidence versions/dates, conditions, risk IDs, exceptions/expiry, contract deviations, allowed data/access, prohibited uses, monitoring, renewal date, and tested exit plan. Sensitive reports and credentials remain in controlled storage.

## Cannot be completed from source code

Vendor representations, contracts, assurance, regions, insurance, viability, incidents, actual configuration, commercial terms, and approval require vendor/company records and qualified review.
