## The envelope

Every event is a `SemesterEvent`. `makeEvent` stamps `eventVersion`, `retentionClass` and a default `dataClassification` from the catalog and defaults `occurredAt` to the current time; the producer supplies the rest.

| Field | Required | Type | What `validateEvent` checks |
| --- | --- | --- | --- |
| `eventId` | yes | `string` | UUID, see rule 2. |
| `eventType` | yes | `EventType` | A key of the catalog, see rule 3. |
| `eventVersion` | yes | `number` | Exactly the catalog version, see rule 4. |
| `occurredAt` | yes | `string` | A time `Date.parse` accepts, see rule 5. |
| `producer` | yes | `string` | A string of 1 to 200 characters, see rule 6. |
| `environment` | yes | `PolicyEnvironment` | One of the policy environments, see rule 7. |
| `tenantId` | no | `string` | A string of 1 to 200 characters when present, see rule 11. A consumer passed an expected tenant also refuses any other (`processOnce`). |
| `customerAccountId` | no | `string` | Not checked at all. Any value passes. |
| `actor` | no | `{ id: string; type: ActorType }` | `{ id, type }` when present, see rule 15. `type` is typed as an actor type but only its length is checked. |
| `subject` | no | `{ type: string; id: string }` | `{ type, id }` when present, see rule 16. |
| `correlationId` | yes | `string` | Matches the correlation pattern, see rule 8. |
| `causationId` | no | `string` | UUID when present, see rule 9. |
| `idempotencyKey` | no | `string` | A string of 1 to 300 characters when present, see rule 10. The database makes `(aggregate_type, aggregate_id, idempotency_key)` unique when it is set. |
| `dataClassification` | yes | `ResourceClassification` | A known classification at or above the type floor, see rules 12 and 17. |
| `retentionClass` | yes | `RetentionClass` | A known retention class, see rule 13. It is not compared with the catalog value for the type. |
| `payload` | yes | `T` | A non-null, non-array object, see rule 14. Its contents are the producer's business and are not validated per type. |

Classifications are ordered `public` < `internal` < `student_private` < `education_record`. Each type's classification below is a floor: a producer may raise it and may not lower it. Retention classes are `operational`, `student_record`, `audit`, `commercial`; a row declares its class so a sweep can apply policy without reading the payload. The durations are policy, in [`RETENTION.md`](../../RETENTION.md), not code.

## What `validateEvent` rejects

A consumer runs `validateEvent` before it reads the payload. The rules run in this order and the first one that fails is the reason returned. `${…}` in a reason marks a value the validator fills in. Unknown extra fields on the event pass.

| # | Reason returned | Fails when |
| --- | --- | --- |
| 1 | `not an object` | The value is `null`, an array, or anything that is not an object (including an empty string, `0` and `false`). |
| 2 | `eventId is not a UUID` | Missing, empty, longer than 200 characters, or not a UUID with a version digit from 1 to 8 and a variant digit of 8, 9, a or b (any letter case). |
| 3 | `unknown event type ${JSON.stringify(e.eventType)}` | eventType is not a key of the catalog. |
| 4 | `${e.eventType} is version ${expected}, not ${String(e.eventVersion)}` | eventVersion is not exactly the catalog version for the type. An older and a newer version are both refused; a consumer does not guess. |
| 5 | `occurredAt is not a time` | Not a string of 1 to 40 characters that `Date.parse` reads as a time. A date alone, such as `2026-10-04`, passes. |
| 6 | `producer missing` | Not a string of 1 to 200 characters. |
| 7 | `environment unknown` | Not one of `production`, `staging`, `demo`. |
| 8 | `correlationId malformed` | Not a string of 1 to 128 characters matching `^[A-Za-z0-9._:-]{8,128}$`. |
| 9 | `causationId is not a UUID` | Present but not a UUID. Absent is allowed; `null` is not. |
| 10 | `idempotencyKey malformed` | Present but not a string of 1 to 300 characters. |
| 11 | `tenantId malformed` | Present but not a string of 1 to 200 characters. |
| 12 | `dataClassification unknown` | Not one of `public`, `internal`, `student_private`, `education_record`. |
| 13 | `retentionClass unknown` | Not one of `operational`, `student_record`, `audit`, `commercial`. |
| 14 | `payload is not an object` | Missing, `null`, an array or not an object. An empty object passes. |
| 15 | `actor malformed` | Present but `id` is not a string of 1 to 200 characters, or `type` is not a string of 1 to 20 characters. |
| 16 | `subject malformed` | Present but `type` or `id` is not a string of 1 to 200 characters. |
| 17 | `${e.eventType} is at least ${EVENT_TYPES[e.eventType].classification}` | dataClassification ranks below the catalog floor for the type. Raising it above the floor is allowed. |

Checks the validator does not make, stated so nobody assumes them:

- `retentionClass` is not compared with the catalog value for the type. `makeEvent` stamps the catalog value; a hand-built event with another known class passes.
- `actor.type` is not compared with the actor types (`user`, `service`, `integration`, `system`).
- `customerAccountId` is not checked.
- The payload is not validated per type.
- Lowering `dataClassification` is refused by `validateEvent`, not by `makeEvent`, and not by the database, whose check constraint accepts any known classification.

## Outbox semantics

The pattern is a transactional outbox. A producer writes the business record and its event row in one database transaction, so a grade is never posted without the event that tells everyone. A publisher reads rows that are neither published nor parked and sends them.

### `drainOutbox(store, publish, options)`

| Behavior | Value |
| --- | --- |
| Default `maxAttempts` | 5 |
| Default batch size (`pending(limit)`) | 100 |
| Rows offered | The oldest pending rows first; a row that is published or parked is not pending. |
| On success | `markPublished(id, now)`; counted as `published`. |
| On a throw | The attempt count is the stored count plus one. Below `maxAttempts`, `markFailed(id, message, attempts)`; counted as `failed`; the row is retried on a later pass. |
| At `maxAttempts` | `markDeadLettered(id, now, message)`; counted as `deadLettered`. The row stays, visible to an operator, and `drainOutbox` does not offer it again. |
| What is kept of an error | The message only, cut to 500 characters. Never the payload. |
| Report | `{ published, failed, deadLettered }`. |

A row is never both published and parked: the table has a check constraint (`domain_outbox_one_outcome`) and `outbox.check.sql` proves it.

### The table `private.domain_outbox_events`

Columns: `id`, `aggregate_type`, `aggregate_id`, `event_type`, `event_version`, `environment`, `tenant_id`, `producer`, `correlation_id`, `causation_id`, `idempotency_key`, `payload`, `data_classification`, `retention_class`, `occurred_at`, `published_at`, `publish_attempts`, `last_error` (at most 500 characters), `dead_lettered_at`. The envelope has no `aggregate_type` or `aggregate_id`, and the table has no `customerAccountId`, `actor` or `subject` column: mapping between the two is a producer's job. The one producer found does it in a SQL function: the envelope's `subject` becomes `aggregate_type` and `aggregate_id`, and `actor` is not stored. The table is service role only; no signed-in account can reach it.

### `processOnce(ledger, consumer, value, handler, expectedTenant?)`

At-least-once delivery means every consumer eventually sees an event twice. `processOnce` runs these steps in order:

1. `validateEvent`. A failure returns `{ outcome: 'refused', reason }`.
2. If `expectedTenant` is given and the event's `tenantId` differs, `refused` with `event is for another tenant`.
3. If the ledger has a receipt for (consumer, event) with outcome `processed` or `skipped`, return `{ outcome: 'duplicate', earlier }` without calling the handler.
4. Run the handler. A throw records a `failed` receipt with the message cut to 500 characters and returns `{ outcome: 'failed', error }`. A `failed` receipt does not block a later delivery, so a handler's external writes must be idempotent in their own right.
5. Otherwise record a `processed` receipt and return `{ outcome: 'processed' }`.

The receipts table `private.domain_event_receipts` has primary key `(consumer, event_id)` and outcomes `processed`, `skipped` and `failed`, so a second receipt for one event is refused by the database too.

A group schema refers to the envelope by `$id`, so load the envelope first. A validator that treats `format` as an annotation will accept more `occurredAt` values than the tests do.

Where the schema and `validateEvent` differ, the test pins the difference rather than hiding it:

- `occurredAt`: the validator accepts anything `Date.parse` reads, including a bare date; the schema requires an RFC 3339 `date-time`. The schema is stricter.
- `retentionClass`: both accept any known class; neither compares it with the catalog value. The catalog value is carried in the schema as an annotation, `x-semesterCatalogRetention`.
- `actor.type` and `customerAccountId` are as loose in the schema as in the validator.
