## D. Tests to write before changing anything (a guard must be seen to fail)

Per the repository's rule: write each against the current code, **watch it fail**, then fix, then restore.

1. **Export withholds guardian restrictions.** Two accounts, a guardian link, a restriction with `court_order = true` and a distinctive note; call `account_export` as student and as guardian; assert neither file contains the note. Control: the same test on a link with no restriction passes.
2. **Erasure clears consent snapshots.** Record, revoke and delete a consent; run `erase_account`; assert no `tenant_policy_audit_event` row mentions the subject's UUID in `old_data` or `new_data`. Control: a different subject's snapshots remain.
3. **Request status changes are audited.** After C3's trigger exists: update a request from `received` to `verifying`, `in_progress`, `completed`; assert one `privacy.request_status_changed` per change, with no free text in `detail`.
4. **Operator is not the requester.** After the answering function exists: calling it as the subject is refused.
5. **Register ↔ retention.** A cheap test that every `site_leads`, `gtm_*` and `support_tickets` table has either a purge job or an explicit "kept, because" line in `RETENTION.md`.

## E. What this pack deliberately does not do

It does not edit `RETENTION.md`, the generated inventory, the PIA, `maturity.ts` or any policy draft: each is held by a test or by the owner's decision. It does not decide the clock, the role split, the notification duty, or the age floor. It does not touch `docs/evidence/`.
