# Tenant boundary map

- **Purpose:** one row per place tenant data can cross a boundary, with what enforces it, what proves it, and what is missing.
- **Scope:** database, Edge Functions, institution gateway, storage, search, cache, queue, worker, analytics, integrations, AI, support, break-glass. Database object counts come from the repo's own catalog reading (`database/*.md`, dated 2026-10-04) or from commands below. Nothing was run against production or a database.
- **Date:** 2026-10-04. **Status:** Phase 0 baseline — evidence-cited, not a readiness claim.
- **Method (commands run from repo root):** `ls supabase/migrations | wc -l` (178); `ls supabase/*.check.sql | wc -l` (110); `grep -rhoiE '^\s*create policy' supabase/migrations | wc -l` (529); `grep -rhoiE 'enable row level security' supabase/migrations | wc -l` (354); `grep -rhiE 'force row level security' supabase/migrations | wc -l` (0); `grep -hE "has_capability\([^)]*'school'" supabase/migrations/*.sql` (351 non-comment lines); `grep -hE 'private\.(same_school|school_of)\(' supabase/migrations/*.sql` (48 lines); reads of `supabase/check.sh`, `supabase/local.stub.sql`, `.github/workflows/ci.yml`, `.github/workflows/functions.yml`. Counts of `create policy` and `enable row level security` are declarations across history, not live objects (see `docs/architecture/multi-tenant-isolation.md`).
- Existing documents are claims. This page links them and says what each proves; it does not copy them.
