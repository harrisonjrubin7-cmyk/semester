# 5 · Legacy retirement plan

Every production file has a proposed owning domain and disposition in
[legacy-inventory.csv](legacy-inventory.csv), generated by
`npm run census:arch -- --inventory <file>` from `app/` (rules in
`app/src/architecture/inventory.ts`). It is a **proposal derived from what a
file does**, not a verdict: the `because` column says why, so a row can be
argued with. Regenerate it; do not hand-edit it.

| disposition | files | lines | meaning |
|---|---:|---:|---|
| reuse | 712 | 182,097 | Pure logic, no ambient dependency, or a shared design-system primitive (≥ 25 importers), or course content. Keep. Wrap behind an adapter now; move into its domain when next touched. |
| migrate | 96 | 32,031 | Touches storage, network, environment or React state. Needs a port and an adapter before it can move. |
| replace | 498 | 145,200 | Screens and components composed over legacy state. Rebuild as thin views of a domain read model, one screen at a time. |
| archive | 81 | 26,836 | Documentation kept as code (governance, ops, trust, registers), imported only by other such files and tests. Move out of the client bundle to ops tooling. Keep their tests. |
| delete-candidate | 61 | 11,883 | No import path from any entry point reaches them. |

Totals include this pull request's 36 new files (34 reuse, 2 migrate). 22
files could not be assigned an owning domain; they are listed as `unassigned`
rather than guessed.

## How each is retired

**Reuse.** No action until touched. The rule: *the second time a legacy
function is wrapped by an adapter, move it into the domain's `domain/`* and
leave the legacy path re-exporting it. The parity test travels with it.

**Migrate.** Cut the port at the seam the audit found: the 15 files that
import the Supabase SDK, then the 59 that touch browser storage directly.
`cloud.ts` first (fan-in 95). The adapter keeps the existing storage key
(ADR invariant 4).

**Replace.** In the order of the phases in [03](03-refactoring-sequence.md):
Today, Work, Calendar. A screen is *done* when it is in
`app/src/architecture/legacy.json` `lockedScreens` — then the next change
cannot re-import `lib/` or `state/` into it.

**Archive.** Verify the 81 are not imported by a product file (the inventory
already downgrades any that are to `migrate`), move them with their tests to
`ops/` tooling, and keep `npm run registers` working. Decision needed from the
owner of `docs/`: where generated documents live.

**Delete.** For each of the 61: (1) confirm no script, glob or dynamic string
loads it (`externalEntries` in `tree.ts` scans `scripts/`, `server/`, `api/`,
`../video`, `../packages` for `src/…` paths, but a computed path would escape
it); (2) delete the file and its test in one commit; (3) the bundle diff and
test count go in the message. Most are in `lib/` (51), then `community/` (6).
Several are plainly documentation generators run by tests (`lib/integration/*`
matrices), which is why this is a candidate list and not a deletion list.

## Retention of requirements

Nothing is deleted for being unfashionable. The earlier audit's capability
matrix (Student home … Data and reporting) is preserved as the domain list in
[02](02-target-architecture.md); the `unassigned` count and the per-domain
table in the census are the traceability check that no area is orphaned.
Dispositions change where code lives, not what the product promises. The
legal, privacy and claims review items in the repository remain gated on
qualified counsel; this plan makes no legal conclusion.

## Done means

- Every `replace` screen is locked or has a recorded reason it is not.
- `legacy.json` `upwardImports` is empty and `cycles` is `{count: 0, largest: 0}`.
- The `lib/` flat folder has no file with a single importer outside its domain.
