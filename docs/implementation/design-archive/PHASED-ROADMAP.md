# Phased roadmap

Phases are evidence gates, not calendar promises.

## Phase 0 — inspection and reconciliation

**Blocked / not passed.** Normalize 281/362/673 screen identities; atomize narrative requirements beyond the 1,595-row catalog; review every retained route/state; establish a current build/test/browser baseline; assign external owners.

## Phase 1 — authority maps and foundations

Reconcile tokens/themes, components, routes, roles/capabilities, documents, and provenance. Produce mapping decisions and characterization tests before behavior changes. Exit with settings/route compatibility, RBAC negative tests, and rejected/aliased entries.

## Phase 2 — coherent user-facing slices

Implement high-value vertical slices using authoritative data and existing patterns. Each needs linked acceptance criteria, unit/integration/browser tests, responsive/accessibility review, and migration/rollback proof.

## Phase 3 — staff, operations, and controlled workflows

Complete authoritative operator workflows for support, registrar, integrations, finance, trust/privacy/security, and `/ops`. Require transition contracts, idempotency/recovery, audit, least privilege, runbooks, and owners.

## Phase 4 — external and institutional activation

Connect real providers/tenants only with signed scope, approved posture, SSO/integration validation, UAT, trained owners, restore evidence, support coverage, and a controlled-launch decision. Deployment or a passing scan alone is insufficient.

## Phase 5 — release and assurance

Run all relevant repository gates, HawkScan for meaningful code changes, production smoke checks, accessibility validation, monitoring, and post-release review. Synchronize the matrix and claim register with observed evidence.
