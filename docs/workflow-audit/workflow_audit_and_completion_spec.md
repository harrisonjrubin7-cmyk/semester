## Registration recovery
Never equate timeout with failure. Reconcile before accepting a conflicting new command. Revalidate at commit. Use new authorized corrections for wrong committed records; never erase historical commands. Do not drop an existing course before replacement is assured. Waitlist, withdrawal and refund policies require institution-specific approval.

### Identity/tenant mismatch
Stop before protected reads. Retry rule: No retry until identity scope fixed. Owner: Identity support. Evidence: Denied-access audit; no protected data disclosed.

### Stale source or unknown authority
Block official command; refresh source and registry. Retry rule: Read refresh only. Owner: Registrar/integration. Evidence: Freshness and writer check.

### Window/time ticket closed
Explain institution rule and next opportunity. Retry rule: Revalidate when window changes. Owner: Registrar. Evidence: No command committed.

### Blocking hold
Permitted reason plus responsible-office handoff. Retry rule: Revalidate authoritative clearance. Owner: Hold-owning office. Evidence: No inferred clearance from task completion.

### Prerequisite/corequisite/credit limit failure
Explain rule; scoped override request if permitted. Retry rule: New preview after changed rule or approval. Owner: Registrar/approver. Evidence: Versioned rule and scoped approval.

### Capacity race/section full
Commit-time capacity check; waitlist or alternative. Retry rule: No blind enrollment retry. Owner: Registration operations. Evidence: One final seat allocated once.

### Repeated same request
Return original status/receipt. Retry rule: Same key and payload deduplicated. Owner: Platform. Evidence: One business effect.

### Same key different payload
Reject conflict. Retry rule: New reviewed command required. Owner: Platform. Evidence: No changed effect.

### Timeout after dispatch
Result unknown; lookup authority and reconcile. Retry rule: No new-key replay; same key only if authority safely deduplicates. Owner: Integration/registrar. Evidence: Resolve before conflicting next command.

### Partial multi-system success
Retain authoritative result; repair projections. Retry rule: Retry projection only. Owner: Integration/platform. Evidence: Ledger agrees; failed projection visible.

### Confirmed precommit failure
Failure with safe resume. Retry rule: Bounded retry after cause clears and revalidation. Owner: Platform. Evidence: Evidence authority did not commit.

### Override expiry or lost permission
Stop; request approval if permitted. Retry rule: No expired approval. Owner: Registrar/security. Evidence: Commit-time role and approval check.

### Waitlist offer expiry/delivery failure
Record expiry under policy; show next action. Retry rule: No unauthorized automatic enrollment. Owner: Registration operations. Evidence: Ordered waitlist; traceable offer.

### Swap/add-drop failure
Preserve original enrollment until replacement assured. Retry rule: Atomic authority operation or explicit approved non-atomic sequence. Owner: Registrar. Evidence: No unintended drop.

### Wrong committed enrollment
Human correction case; assess policy and impacts. Retry rule: New auditable correction, never erase history. Owner: Registrar. Evidence: Original plus correction ledger.

### Withdrawal/refund mismatch
Retain academic decision; reconcile financial difference. Retry rule: No automatic academic reversal. Owner: Registrar/student accounts. Evidence: Separate academic and financial receipts.

### Cutover/authority drift
Pause scope; reconcile in-flight commands and writer. Retry rule: Resume only after authority gate. Owner: Implementation/registrar. Evidence: No split-brain writer.
