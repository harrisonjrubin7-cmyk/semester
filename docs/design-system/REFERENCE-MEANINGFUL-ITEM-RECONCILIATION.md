This register is the first capability-level layer above [`REFERENCE-ARCHIVE-INVENTORY.csv`](REFERENCE-ARCHIVE-INVENTORY.csv). The file inventory says what each archive file is as evidence. This register says what the meaningful product or program item maps to in the current repository. Each row has exactly one disposition from the integration brief. A repository path is evidence to inspect, not proof of deployment, institutional authorization or production enablement.

## Disposition rules used here

- **Existing and verified** requires a current repository implementation and a named automated guard for the bounded claim in the row.
- **Existing but incomplete** means part of the capability is real, but at least one required layer, state, authority boundary or release gate is absent.
- **Missing and in scope** is used only when current authority permits the capability, no implementation exists and dependencies can be named.
- **Duplicate or superseded** applies to an archive deliverable or proposed parallel authority already replaced by a current repository authority.
- **Documentation or roadmap only** does not authorize product work by itself.
- **Blocked by external authority, credentials, vendor, environment, legal review, staffing, or institutional decision** is used only when no honest repository completion is possible without that prerequisite.
- **Intentionally excluded with a repository-backed rationale** names the controlling repository decision.
