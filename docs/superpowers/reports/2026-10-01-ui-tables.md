## Outcome and shared interfaces

The shared human-table contract now covers **31 record, decision, or derived-result table instances**, including actual registration comparisons, academic records, student accounts, grading, migration/integration work, personal planning, public calculators, and spreadsheet pivot results. Source calculations, unknown labels, provider handoffs, and React business controls stay in their original workflows.

- `app/src/components/HumanTable.tsx`: generic `HumanTable<T>` takes authorized rows, stable `rowId`, and typed `HumanColumn<T>` definitions with explicit `value` and optional `render` accessors. `renderCards` receives filtered rows and preserves native comparison cards and plan selectors. `summaryPrimary` keeps decision essentials prominent while putting supporting questions in native disclosures. The default card/summary renderer uses named articles and definition lists. Table mode has captions and scoped headers.
- `RecordTable`, `TableRecord`, `RecordCell`, and `RecordColumn` adapt dynamic matrices. Every cell supplies its public display value separately from its original React content. The shared code never inspects the DOM, serializes React controls, enumerates source-record properties, or executes control callbacks while changing views.
- `app/src/lib/human-table.ts`: `HumanView`, `TableCriteria`, `SavedTableView`, `TablePreferences`, strict bounded preference validation, and working-view CSV. CSV delegates to the existing safe gradebook cell encoder, with additional protection for formula prefixes after whitespace/control characters. Existing `download` delivery is reused.
- `HumanTableOwner` scopes institutional preferences by tenant and authenticated viewer; gradebooks scope by viewer/course/term. Other tables use the existing account-ID hook, or an explicitly separate local-device scope when signed out. Institutional/gradebook children remount when their owner changes. Criteria never become evidence of permission.
- Device storage key: `semester.human-tables.v1:<encoded-owner>:<encoded-table-id>`. Only the chosen view, search, filter criteria, and up to 20 named views are persisted. Rows, cells, source records, grades, and React content are excluded by the validator. Failed writes leave the working view usable and retain previous saved bytes. These device-only criteria are explicitly exempted from student workspace backups because institutional search strings and tenant filters must not be rebound to a different account/role.
- The standard offers visible-row CSV only where the existing data policy allows it. Files and on-screen copy say **working view, not an official signed record**. Official exports, receipts, release controls, and confirmations remain separate and unchanged.
- Graduation planning loads lazily when Degree's planning tab opens. Existing bundle limits remain unchanged.
