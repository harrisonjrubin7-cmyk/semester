# Incident response runbook

1. **Detect and open:** create incident ID; timestamp; reporter; environment/tenant; suspected severity; preserve minimal evidence.
2. **Protect:** stop harmful writes, disable feature/provider, revoke access/token, isolate tenant or enter read-only mode. Do not destroy evidence.
3. **Assess:** affected systems/data/users; confidentiality/integrity/availability; ongoing risk; legal/contract notice clocks.
4. **Coordinate:** incident commander, security, privacy/counsel, engineering/ops, support/comms and customer contact. Name next-update time.
5. **Communicate:** verified facts, impact, safe workaround, action requested and next update. Do not speculate or expose student data.
6. **Eradicate/recover:** fix, rotate/revoke, restore/reconcile, validate authorization/data integrity, monitor and document rollback.
7. **Close/learn:** customer/regulatory notices as advised, timeline, root cause, control failure, corrective actions, owners/dates and evidence update.

P0/P1 pauses launch or active pilot until the responsible owners approve safe recovery. Run a tabletop before launch and at least semiannually; file timing, decisions and gaps.
