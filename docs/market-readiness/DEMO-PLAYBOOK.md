# Demo playbook

Use synthetic data only. State at the start that official university records remain authoritative and that no live institutional connection is being shown unless one is actually approved.

## 20-minute executive demo

1. 2 min — the registration-readiness problem and narrow pilot.
2. 5 min — student lands in Today, sees source/freshness and next action.
3. 4 min — registration checklist, schedule/workload and support path.
4. 3 min — manual setup and recovery from a wrong input.
5. 3 min — aggregate pilot scorecard with privacy threshold.
6. 3 min — implementation, trust gates and conversion/clean exit.

## 45-minute operational demo

Add onboarding, empty/loading/error/recovery states, notification preferences, help, export/deletion, degraded/read-only state, admin cohort/feature view, audit example, support escalation and offboarding.

## Technical/security demo

Show architecture/data flow; tenant/resource policy; roles/capabilities; audit; secrets/CI; sandbox separation; integration journal; read-only/kill switch; rights lifecycle; monitoring/runbooks; evidence gaps. Do not display secrets, real student data, internal exploit details or unsupported certifications.

## Student demo

Manual start → add one course/calendar source → confirm first-week plan → complete one useful action → adjust reminders → find support → export/delete explanation. Target 10–15 minutes.

## No-integration demo

Demonstrate that manual setup produces value without school credentials, roster, grades, holds or SIS access. This is the fallback offer and the default when approval is uncertain.

## Stop conditions

Stop or reframe if the demo environment exposes real records, a flow fails closed without an explained workaround, the prospect requests prohibited data/high-impact AI, or the script would imply an unapproved integration/customer relationship.
