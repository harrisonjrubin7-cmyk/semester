# Information security questionnaire

**Status:** response framework for evidence-backed review; not a completed certification or customer-specific answer set.

For each customer question, record: question ID, exact response, status (`IMPLEMENTED`, `PARTIAL`, `PLANNED`, `NOT APPLICABLE`, or `UNKNOWN`), repository/control evidence, production evidence, owner, review date, customer-specific configuration, gap/remediation, and approver. Never convert design intent into “yes.”

Required sections cover governance/ownership, architecture/hosting, identity/access, tenant isolation, encryption/key handling, secure development, vulnerability management, logging/monitoring, incident response, continuity/restore, data inventory/retention/deletion, subprocessors, privacy, AI use, accessibility, integrations, support, and offboarding.

Use [HECVAT-EVIDENCE-MATRIX.md](HECVAT-EVIDENCE-MATRIX.md), [PROCUREMENT-QUESTIONNAIRE-PROCESS.md](PROCUREMENT-QUESTIONNAIRE-PROCESS.md), and [the response pack](../launch-readiness/SECURITY_QUESTIONNAIRE_RESPONSE_PACK.md). Security, privacy, counsel, accessibility, operations, and customer owners must approve their sections before release.
