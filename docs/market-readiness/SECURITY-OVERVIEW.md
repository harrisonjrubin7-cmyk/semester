# Security overview

Semester’s repository includes tenant/role controls, row-level policies, audit structures, fail-closed feature activation, data-rights machinery, secure-secret boundaries, recovery controls, and security documentation. These are implementation claims, not an external certification or proof of a live customer environment.

Before a paid pilot, Semester must complete a target-environment security review, authorization/isolation acceptance, current vulnerability and penetration assessment, monitoring/alert review, incident/restore exercise, subprocessor approval, and closure of every P0/P1. No SOC 2, FERPA-compliance, penetration-tested, encrypted-everywhere, or enterprise-security claim may be made unless current evidence directly supports it.

Procurement evidence is indexed in [SECURITY-CONTROL-MATRIX.md](SECURITY-CONTROL-MATRIX.md), [HECVAT-EVIDENCE-MATRIX.md](HECVAT-EVIDENCE-MATRIX.md), and [the launch-readiness security overview](../launch-readiness/SECURITY_OVERVIEW.md).
