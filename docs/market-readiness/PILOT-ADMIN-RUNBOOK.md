# Pilot administrator runbook

Before launch, verify tenant/cohort identity, sponsor/champion, data mode, enabled and disabled features, roles/capabilities/expiry, support/escalation, measures/privacy thresholds, known limits and rollback. Use synthetic data until production-data approval.

Daily during launch week: review health/errors, integration freshness, support/accessibility/privacy cases, invitations/activation and open incidents without inspecting student content. Weekly: review aggregate scorecard, access changes, findings, costs and decisions. Privileged changes require reason, capability, tenant/resource scope and audit record.

Pause when a P0/P1 appears, tenant/data scope is uncertain, monitoring fails, support is unavailable, or a required owner withdraws. Offboard using the dedicated playbook.
