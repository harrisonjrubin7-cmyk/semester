## 1. The claim, and what it replaces

**Proposed wording (scoped):**

> Where Semester shows a source label beside a fact, the label says where the
> fact came from — institution verified, imported, student entered, estimated,
> AI-assisted or needs review — and, where it is known, when it was last updated.

**Not supported by this evidence:**

- "Every fact in Semester says where it came from" (this is `M-09` as it stood in
  [`BRAND-AND-MARKETING-STRATEGY.md`](gtm/BRAND-AND-MARKETING-STRATEGY.md), and the
  first draft of the brand promise). Labels appear on the surfaces in §3. No test
  or inventory shows coverage of all facts, and
  [`where.ts`](../app/src/lib/where.ts) records, in its header, that Today put
  facts of different origin in one list "looking identical" before per-row labels.
- That any label is populated from a live institutional system. See §4.
- That a "report incorrect information" control accompanies each label. Only two
  call sites pass `onReport` (`components/ActionCenter.tsx`,
  `components/room/Talk.tsx`).

## 2. The mechanisms, and which one carries the claim

There are three, and they are easy to confuse.

| Mechanism | Source | Vocabulary | Where it renders |
| --- | --- | --- | --- |
| **`SourceBadge`** (carries this claim) | `components/SourceBadge.tsx`, `lib/source.ts` | Institution verified · Imported · Student entered · Estimated · Needs review, plus display-only AI-assisted and External; `unavailable_stale` is also defined | 30 component and screen files (§3) |
| **Provenance ladder** | `lib/where.ts` | Official · Connected · Made here · Yours · Sample · Out of date | Calendar and Connect feed rows only; the badge prints only for `official`, `sample`, `stale` (`worthSaying`) |
| **`StatusChip`** | `lib/status.ts` | 16 status keys (e.g. Needs confirmation, Synced, Offline) | `needs-confirmation` is the only key written as a JSX literal, in `NotOfficial.tsx` and `TodayDecisionSurface.tsx`. The `unity/` components (`ContextBar`, `ObjectCard`, `UnityLayer`) take keys as props from callers such as Pathway, Courses and Guide, and `SystemContextBar` derives one from sync state; I did not trace which keys reach the screen |

The trust-cues document lists `faculty-approved`, `course-provided` and
`updated-today` as defined but unused. This pass found no use of them as status
keys outside `lib/status.ts` and tests, but props passed to the `unity/`
components were not traced, so treat them as **unconfirmed**, not as absent.
`official` is never returned for feeds in this build (`where.ts` header;
`where.test.ts` asserts feeds are never `official`).

## 4. Open item: "Institution verified" is written unconditionally

Four components print `institution_verified` as a literal, with no check on where
the data came from: `OfficeActionFeed`, `OfficeActionsToday`, `StudentRegistration`
(sections) and `StudentGrades` (released grades). The label is accurate if the
rows were published by institution staff inside Semester. It would be **wrong** if
any path can show sample, seeded or student-held data under it.

I did not trace the data path for each. Because no institution is live
(`CLM-013`, `CLM-005`), the only data that can appear today is demonstration or
internally seeded data. **Product and Engineering should confirm, per component,
that the label cannot appear over non-institution data before `CLM-018` is
approved.** Until then the public wording must not name "institution verified" as
something a student currently sees.

## 6. Limits

- Not run in a browser; not tested with assistive technology. The badge renders
  text, not colour or shape alone, and `a11y/tellings.test.ts` is the guard the
  component cites, but no conformance conclusion follows (`CLM-008`).
- The surface list can only grow or shrink with the code. The guard stops this
  document from overstating; it does not require new surfaces to be added.
- "Last updated" is shown only where a timestamp is passed (`at`). `unknownAge`
  exists so a badge can say the age is unknown, and is opt-in.
