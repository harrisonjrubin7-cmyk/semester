# Compliance and security evidence

This maps controls to artefacts. It is **not** a claim of SOC 2, ISO 27001 or
FERPA compliance; those need an auditor or counsel (`docs/COUNSEL-BRIEF.md`).
It makes the evidence a reviewer would ask for exist, timestamped, and tied to a
commit.

| Control | Artefact | Produced by | Retention |
| --- | --- | --- | --- |
| Changes are reviewed and approved | PR review, `CC-<pr>.md`, ruleset JSON | GitHub + `infra/changes/` | permanent (git) |
| Production changed only via pipeline | apply run, saved plan, converge check | `infra-apply.yml` artifacts `plan-*` | 400 days |
| No undetected drift | daily plan text + JSON + hash | `drift.yml` artifacts `drift-*` | 400 days |
| Policy enforced | `scripts/infra/policy.sh` output in CI | `infra.yml` | CI logs |
| Software inventory | CycloneDX SBOM | `pages.yml`, `supply-chain.yml` | 90 / 400 days |
| Build integrity | signed provenance + SBOM attestation | `supply-chain.yml` (GitHub attestations) | per GitHub |
| Least privilege | Terraform for permissions/environments; access reviews | `infra/`, `reviews/` | permanent |
| Recovery tested | dated drill write-ups | `docs/infrastructure/drills/` | permanent |
| Exceptions are time-boxed | `exceptions.json` + expiry test | `infra/policy/` | permanent |

Bundle for an auditor or a customer's security questionnaire: the commit SHA,
the `plan-*`/`drift-*` artifacts for the period, the latest SBOM and its
`gh attestation verify` output, the change records merged in the period, the
latest access-review and drill write-ups, and `exceptions.json`. Assemble with
`gh run download` per workflow; nothing here is generated by hand.

Honest gaps today: no drift or apply artifacts exist until activation; no drill
or access review has been run; backups are unverified (R-7).
