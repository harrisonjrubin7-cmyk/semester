## D-1267 · GitHub's Pages starter workflows are removed, not registered

**Decided 5 October 2026.**

`jekyll-gh-pages.yml` and `static.yml` were added to `main` through the web editor (`96b75be`, `8dffef1`) and are removed here. Both deploy to GitHub Pages on every push to `main`; `static.yml` uploads `path: '.'`, the whole repository, and both would race `pages.yml`, the real deploy, for the same site. Neither had deployed when they were found (the first `static` run was cancelled, the two Jekyll runs failed and were cancelled), so nothing was published.

They also failed two guards that require every workflow to be named, `developers.test.ts` (the testing guide) and `sre/sre.test.ts` (the SRE catalog), which were red on `main`. The alternative to deleting was registering both in those two places. That would have documented a deploy that publishes the repository root, so it was not taken.

**If a second Pages site is wanted,** add it deliberately: a path that names only the files to publish (never `.`), a row in the testing guide and in the SRE catalog, and a `concurrency` group shared with `pages.yml` so the two cannot deploy at once.
