## D-1165 · Implementation is ten phases over nine stored stages, and the method may not invent a stage the database would refuse

**Decided 4 Oct 2026.** The institutional implementation and customer success
method lives in `docs/institutional-implementation/` (a separate folder:
`docs/implementation/` holds per-increment delivery notes).

- **Ten phases, nine stored stages.** Discover, design, configure, integrate,
  migrate, pilot, parallel run, go-live, hypercare and optimize are milestones
  inside the stored `implementation_projects.stage` values; training is the
  stored stage `train`, a gate before the pilot. No stage value is added.
- **Rollout state is a record, and its exit gates are the method's exit
  evidence.** The methodology's gate table is held equal to
  `private.rollout_exit_gates` by `app/src/lib/ops/implementation-system.test.ts`.
- **Seats, not people.** Every seat names a primary and a backup; a seat with
  no backup is `at_risk`; maker-checker pairs are never collapsed.
- **Health weights are not re-tuned.** The proposed model in
  `docs/commercial/CUSTOMER-HEALTH-SCORE.md` stands; the test holds the
  weights equal. Renewal posture is rules-based and human-reviewed, with no
  predictive claim.
