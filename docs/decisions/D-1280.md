## D-1280 · The soak fails on a drift only when it persists over a second run of windows

**Decided 2026-10-05**, on the owner's "go ahead" to the option of keeping the drift gate blocking and its limits unchanged while requiring the drift to persist. It answers the "decision for the owner (cause 2)" left open in `docs/evidence/operations/2026-10-04-main-ci-red-diagnosis.md`.

**What.** `supabase/load/run.sh` runs the soak's four windows and `drift.sh` judges them as before. If `drift.sh` fails, the soak runs four more windows and judges all eight by the same rule, with the same limits (`SOAK_RATIO` 2, `SOAK_MIN_DELTA_MS` 5), and the run fails only if the drift is still there. A typical window over budget is re-judged over the longer run the same way. An error, a broken invariant and a leaked connection fail in the window they happen in and do not wait for this. A run that sees no drift in four windows is exactly as before.

**Why.** The rule compares the best of the first quarter of the windows with the best of the last, at least two each. With four windows each end is two windows, so a fast pair at the start against a stalled pair at the end reads as a leak. It failed `main` run 4205 (`sync-push`, 23.6 to 57.6 ms) and failed #1280 twice, once on `plans` (17.4 to 52.8 ms, with the typical window at 42.9 ms against a budget of 60) and once on `sync-push` (20.8 to 52.0 ms): different scenarios, no change to any SQL or application file. A leak is still there when the soak runs on; runner contention usually is not. Disabling the check, making it report-only, or loosening the limits would each have weakened what it was written to find (D-1019); this does not.

**Not done.**
- The limits are not retuned and the number of windows in CI is unchanged (`LOAD_SOAK_WINDOWS: '4'`).
- No false-positive rate has been measured. The diagnosis's closing evidence stands: ten consecutive green `main` runs with the causes absent. If the drift step still fails alone on `main` after this, the next options are the ones that document lists.
- A drift that only appears after window five is judged by the eight-window run, whose quarters are still two windows each.
- Run cost goes up by about the soak's own duration, only on a run that flagged a drift.

**Seen red.** `app/scripts/soak.test.ts` runs the block of `run.sh` with the database stubbed out and `drift.sh` real. With the confirmation loop replaced by a no-op, two of its three new tests fail (the lucky-pair case fails the run at four windows, and the leak case does not reach eight); restored, all 40 tests in the file pass. The cases are a clean four windows (no extension), a lucky early pair against a stall that clears at eight windows (passes), and a leak that climbs to 110 ms (fails at eight).
