## D-1144 · Adopt a modular-monolith target architecture as the proposal, and convert by strangler

**Decided 2026-10-04 (proposal status: the architecture review accepts each proposal separately).** The target is one container-hosted `core` with enforced module seams, plus three separate deployables from day one: `ai-gateway`, `integration-hub` and `sync-gateway`. The existing React/Vite/Supabase implementation is converted by strangler waves, not rewritten: extract pure domain logic, put a contract in front, shadow, switch behind a ring flag, then retire the old path only after a full release train of parity evidence. The pack is [`docs/target-architecture/`](../target-architecture/README.md).

This tests ADR 0003 ("no application server"), which said Phases 6–15 would test it. It does not propose microservices and does not override the platform constitution: extraction needs a written trigger. The 14 technology proposals (P-01 to P-14) stay proposals; each becomes an ADR in its own pull request when a phase needs it.

Not decided here and not done: no code, workspace, migration or flag changes; the cloud and region posture (P-12); the navigation question (the audit's ten areas against `DO-NOT-BUILD.md` rule 1); funding and hiring; every legal conclusion, which stays with qualified counsel.
