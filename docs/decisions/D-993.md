## D-993 · Assignments and submissions exist for a school that runs `lms_assignments` in Core, and only then

**Decided 1 Oct 2026 (Prompt 3 of the Core briefs; the owner asked for the
open prompts to be taken to done in order).** D-151 and D-152 made Core a
per-module, per-school setting. This is the first LMS module behind it.

- **Only in Core.** Every writer in `20261001010000_assignments.sql` refuses
  unless the school's `lms_assignments` module is Core, not frozen, and
  `kill.core_modules` is disengaged. In Connect the school's own learning
  system is the record; a row here would be a second one.
- **Who.** `assignments:author` (faculty), `assignments:extend` (faculty,
  teaching assistants), `assignments:review` (faculty, teaching assistants)
  and `assignments:submit` (the student roles, which is the roster), each held
  over `<school>/<CODE>/<TERM>` as the gradebook's are. A grant with no term
  authorises nothing.
- **The clock is the server's.** `submitted_at` is read inside the writer;
  there is no argument to pass one. Late is that instant against the due date
  the student is held to, which is their extension if they have one.
- **Rules.** Late work is refused or taken (flagged late), with an optional
  cut-off; `attempts_allowed` is enforced under an advisory lock per student
  and assignment; every writer takes an idempotency key, so a double click is
  one submission and a reused key for another request is refused.
- **Append-only, with a receipt.** Submissions, files, receipts and
  extensions are never rewritten, even by the table owner. A receipt carries a
  SHA-256 over the server time, attempt, lateness and the work's own hashes.
  It is not a grade.
- **Files** go to the private `assignment-submissions` bucket under
  `<school>/<assignment>/<student>/<name>`; Storage lets a student write only
  their own folder of a published assignment they are on the roster of, and a
  submission may name a file only if the object is there.
- **`schools.timezone`** is added (the completeness matrix asked for it when
  Core began to serve term dates), checked against the database's own list.
- **Where it shows.** An Assignments section on the Gradebook screen, not a new
  screen and not a new navigation root: the instructor's half for an author,
  the student's half for the roster, and one sentence in Connect.
- **Proof.** `supabase/assignments.check.sql`, 87 checks. Red when the Core
  requirement is removed, when the attempt limit is removed, when the late
  refusal is removed and when the roster check is removed; each restored.
- **Not done here, on purpose:** group submissions and group extensions
  (an extension is per student), virus scanning of uploads (P7), the
  instructor's grading view of a submission (the gradebook's), and anything
  that makes a student's grade from a submission: AI never decides a grade.

### Attendance (Prompt 5, first half)

`20261001020000_attendance.sql`, on the same footing: only in Core (the
`attendance` module), roster by `attendance:attend` and `attendance:take` over
`<school>/<CODE>/<TERM>`.

- **A code is a secret for one session.** Six digits, made by the server, unique
  among a school's open sessions, readable by takers and by no student. A wrong
  code is *answered*, not raised, so the try is kept; five in ten minutes stop
  that person's check-ins for the window, even with the right code. A right code
  from someone not on the course is answered as a wrong one.
- **Server clock.** Present inside the late window, late after it, refused
  outside the open window.
- **Marks are versions.** A change is a new row with who and why; the owner
  cannot rewrite one. An excused absence needs a note. Closing a session marks
  the roster's unmarked students absent, once.
- **Refused, not deferred:** location or device checks, photographs, and any
  measure of attention (the brief's "no emotion or attention monitoring").
- **Proof.** `supabase/attendance.check.sql`, 60 checks; red when the Core
  requirement, the lockout, the roster check or the late line is removed.

### Question banks and timed tests (Prompt 5, second half)

`20261001030000_assessments.sql`, behind the `lms_assessments` module.

- **A student is never sent a key.** The keys are in `bank_items`, which only
  reviewers read. `assessment_items` returns stems and options and nothing
  else; `assessment_review` shows what was right only if the instructor chose to
  and the test has closed.
- **The clock is the server's.** `started_at` and `deadline_at` are read inside
  the writer. Past the deadline a save is *answered* `time_up` (not raised, so
  the finish is kept) and the attempt is finished as expired with what was
  saved. Starting again on any device returns the attempt in progress with the
  time that is left. A refresh of a pool is the same questions.
- **Pools** are drawn when the attempt starts and fixed on it.
- **Extra time** is an explicit per-student, per-test percent with a short
  reason that is not a diagnosis; `accommodation_passports` holds a functional
  summary in words and is never read here.
- **Scoring** is the instructor's key applied by rule: a choice, a set, true or
  false, a number within a tolerance, a text after trimming and case-folding. An
  essay is not scored and flags the attempt `needs_review`. The score is a figure
  on the attempt, not a grade: nothing here writes the gradebook, and AI decides
  nothing.
- **Never rewritten:** finished attempts and their answers, extra time, and bank
  items (retired by a stamp). The guards allow only clearing the author's name
  when that person's account is deleted; the check suites for assignments and
  attendance now delete the staff who wrote a row, which found the same flaw in
  both earlier guards, fixed here.
- **Refused, not deferred:** biometric proctoring, and any emotion or attention
  monitoring. Nothing records where a student looked or which window they were
  in.
- **Proof.** `supabase/assessments.check.sql`, 108 checks; red when the Core
  requirement is removed, when a key reaches the student, when the server
  deadline is ignored, and when the numeric tolerance is ignored.
- **Not done:** QTI 3 import and export (next), and writing a test score to the
  gradebook (an instructor releases a grade in the gradebook, by hand).
