## D-1582 · The university records RLS reference is held out of `supabase/migrations` until one role model is chosen

**Decided 2026-10-13.**

`origin/main` already runs a live role model: `public.role_grants` (20+ roles) and `private.holds_role()`, referenced from 15 migration lines. The uploaded reference adds `private.role_grants` (seven roles), its own session context, and a custom JWT claim. Adding it as a migration would create two sources of truth for the same grants.

So the reference is kept under `docs/ecosystem/reference/university-records-rls/`, where it is reviewable and reproducible but does not run on deploy. It passes 73/73 pgTAP assertions on PostgreSQL 16 with a minimal auth shim.

Not done: choosing the canonical model, any data migration between them, and any change to the live Supabase project.
