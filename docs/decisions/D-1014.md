## D-1014 · Every capability is held to one of twelve primitives, and what the tree lacks is stated rather than assumed

**Decided 30 Sep 2026.** Four briefs arrived together: learner journeys and
trust systems (15 areas), institutional intelligence (12), a completion
framework (twelve primitives, twelve admission questions, P0–P5), and the
missing departments, roles and operating functions. The owner asked for them
to be executed. Read against main, none of the 37 named capabilities is
complete; 27 are partial and 10 are absent.

- **A register, not a promise.** `lib/governance/constitution.ts` holds the
  primitives, the eleven-part constitution, the twelve admission questions,
  the priority order, the 37 capabilities (each with its primitive, priority
  and the file that holds part of it, or nothing), 33 departments with the
  line each does not cross, and 56 roles with the ten things every role is
  defined by. `constitution.test.ts` holds each citation to the tree and
  states the counts; `docs/PLATFORM-CONSTITUTION.md` is rendered from it.
  Identity and Learning have no named gap and the test says so.
- **Three capabilities, built and then wired where the repository supports it.**
  Each stays *partial* in the register, because each is behind a flag that is
  off by default and none reaches a school.
  - `automation` (the ladder, inform → verify) lives in
    `packages/institution/src/automation.ts`, the contract the browser, the
    gateway and the tests all share. The gateway's commit path asks `mayStep`
    from confirm to execute, with grounds read from what it already checked
    (`groundsFor`: the explicit `true`, write access to the area, the action
    the adapter offered, the correlation id), before it claims the action; a
    refusal names what is missing. `automationrungs.ts` declares the rung of
    eight features and a test holds each to a file, to one step, and to its
    grounds — only the gateway's commit stands at execute.
  - `lifeevents` is the panel **If something has changed** on Behind, behind
    `VITE_ME_LIFE_EVENTS`: twelve sentences, no field to type in, optional
    adjustments, help routes that seed Help with nothing filled in, a plan that
    clears itself at 28 days with one follow-up at 14. It is kept on the device
    under its own key (`useDeviceLibrary`, per account), outside the synced
    state, and sent nowhere. It is on Behind and so appears once a term is
    imported; it is not on Today or in Help.
  - `momentfeedback` asks two of its eight moments — after an Ask Semester
    answer that has a source, and after a help request is sent — behind
    `VITE_ME_MOMENT_FEEDBACK`, and What's new shows "You said, we changed"
    (empty, and saying so) with the switch, the count and a two-step delete.
    One fixed-choice question, no free text, one prompt a day, thirty days
    between asks of a moment, never again after three skips, an off switch.
    "Asked" means shown: a prompt is written down when it is drawn, so walking
    away without answering still uses the day and the thirty days.
    Answers stay on the device. **There is no collection path to a school**, so
    `aggregate` and its cohort floor are the shape one would take, not something
    that runs; the panel says the answers are not sent. Six moments are declared
    and not asked (`WIRED`, held to the tree by a test).
  Both device stores are named in the workspace-backup coverage test as exempt,
  with reasons: a choice made without giving a reason, and optional answers that
  are not the student's work, should not ride into a downloaded file by default.
  That is a decision, not an omission, and it is the first place to reopen if a
  school asks for these in a student's export.
  Neither flag follows the institutional preview; both are registered in
  `pages.yml` and `SECRETS.md`. Guards shown failing and restored: the ladder
  call removed from the commit path, the panel drawn with its flag off, the
  slot touching the store with its flag off, the send question asked before a
  send, a stored category trusted over the moment's, a plan drawn on the day it
  clears, plus the four from the first pass.
- **Not built, and why.** The ten absent capabilities (playbooks,
  credential network, content layers, workflow
  marketplace, policy engine, digital twin, accreditation, survey
  operations, BI connectors, mobile ID) each need a data model, a migration
  or an owner that does not exist yet; the register says which, so the
  next one starts from a stated gap. Mobile ID is bounded in advance: no
  location tracking, no access-log browsing as a student feature.
- **Constraints kept.** No new top-level navigation item (DO-NOT-BUILD rule
  1), so "My Network" has no root; no invented pass for a primitive with no
  gap; nothing here reads the network, database or clock.
