## D-1538 · The registration-readiness pilot's contracts are versioned YAML, checked in CI, and the pilot stays NO-GO until its evidence exists

**Decided 2026-10-13.**

The pilot spec's contracts (capabilities, records, routes, workflows, events, audit keys, OpenAPI and AsyncAPI) live under `docs/contracts/` as YAML, and `scripts/validate-pilot-artifacts.mjs` checks them against each other and against the migrations they name. The check runs on every pull request that touches those paths (`.github/workflows/pilot-contracts.yml`).

Why: the spec's contracts were prose. A route can name an operation that does not exist, a document can cite a control that was never written, and a release can be called GO with evidence that is still pending. A check that runs in CI turns each of those into a failed build instead of a review comment. The GO refusal is the one that matters most: `docs/launch/go-no-go.yaml` cannot say GO while any evidence item in `docs/governance/release-evidence.yaml` is not verified.

Also decided:

- The architecture documents are Markdown with their rules in fenced YAML. The spec named both `.md` and `.yaml` for them; one file per document avoids two copies drifting.
- The validator uses the `yaml` package as a root devDependency. The platform-control registry has no dependencies and uses JSON; YAML was kept because the spec named YAML, and the package is build-time only.
- The pilot is NO-GO. Institution sign-off, the pilot institution, and the named owners are not known, so the gate decision is not made on anyone's behalf.

Deprecated: nothing. Superseded: nothing.
