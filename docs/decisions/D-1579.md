## D-1579 · Activation gates live in the platform-control registry, not in a parallel YAML tree

**Decided 2026-10-13.** The pilot brief names `registry/` and `evidence/` YAML paths. Neither exists in the repository. The platform-control registry (`packages/platform-control/registry/`, JSON, validated by `npm run registry:validate`) already governs capabilities, scopes, and release decisions, so the activation gate is a new group in that registry rather than a second source of truth.

Consequences:
- A gate's status is derived from its items and a recorded decision. Nobody can set `ready` by hand.
- A capability marked `tenant_activated` without a ready gate fails validation.
- The gate's evidence paths use the existing repository-path check.
- Only one item is `passed` today (policy tests). The other 20 stay `not_verified` until institution, operations, or trust evidence exists.

Not decided here: the content of the trust-status register, data inventory, AI review packet, and legal workstream tracker. Those exist as documents under `docs/` and are not restructured by this change.
