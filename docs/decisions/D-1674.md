## D-1674 · Documents kept in Semester live in Mine as a Documents tab, and sharing evidence with employers lives in Career as an Employers tab that also shows an employer what was shared with it

**Decided 2026-10-21**, by the assistant wiring screens for #1661 (D-1661) and #1670 (D-1670). The founder can overrule any of it. No hosted database is touched; both migrations still wait on the owner.

**1. Documents are a fifth Mine segment, not a new place.** Mine is "everything you added yourself". Its Notes and Files tabs are the student's own work on the device, and a document kept in Semester is the same kind of thing, kept on the school's service instead. No new top-level navigation was added. The `MineTab` union grows by `documents`; `mineTab` stays ephemeral, as before.

**2. It is a separate editor from Write, for now.** D-1661 §8 named the first adopter as a "Save a version to Semester" action in `screens/Write.tsx`. That needs a mapping from a device document's blocks to an object, and it is not done here. Mine › Documents edits plain text or Markdown under `semester.document/1`. Write is untouched. When Write gains the action, its saved documents appear in this same list.

**3. Sharing a document is by account id, and the student's own id is shown.** #1661 grants to an account and never looks anyone up, by design. No screen showed a person their account id, so Mine › Documents now shows it with a Copy button. A people lookup is not added.

**4. Employer sharing is its own Career tab, Employers, and is not behind `career_evidence`.** That module flag gates the device-only Evidence tab (Phase I), which is off by default and is a different store. The server-backed share says for itself when it is not set up, signed out, or in a local-only build. Folding it into the flagged tab would hide a working feature behind an unrelated switch.

**5. An employer's "Shared with you" is in the same tab, shown only to an account with a live employer role.** The app reads the caller's own `role_grants` to decide this. The table's policy lets a person read their own grants. That read authorizes nothing: `career_evidence_shared_with_me` re-checks the role on every call. `role_grants` is added to `OWNED_TABLES`, since it cascades with the account, and to `NOT_CONTENT` in `ltiaccount.test.ts`, since a grant is not something the person made.

**6. History and shares are read from the tables, not from new functions.** The owner's RLS on `workspace_object_versions` and `workspace_object_grants` already allows these reads, so `listVersions` and `listShares` select metadata only, with no body. No migration changes.

**Not done:**
- a screen for someone given a document share to see what was shared with them;
- comments, because there is no comment store;
- a grantee's edit flow;
- the Write integration;
- employer onboarding.
