## D-1416 · A guardian projection requires verified relationship and scoped consent; neither is authority alone

**Decided 9 October 2026.** This records the Milestone 7 repository
foundation. It does not activate a tenant or amend D-150's separate SCIM and
SSO hosting decision.

- The existing K–12 `guardian_links` row remains relationship evidence, and
  the existing `family_grants` row remains the student's scoped consent. A
  guardian projection requires both to name the same school, student,
  guardian and exact resource. Neither row grants institutional-record access
  by itself.
- The first projection is deliberately calendar-only. It stores only a title,
  time, status, source version/freshness and expiry. It is not a generic JSON
  copy and is not a route to grades, transcripts, enrollment, submissions,
  aid, health, conduct or support cases.
- Publication is service-only and the backing projection and audit relations
  grant no table access to browser roles or the service role. The guardian's
  only read function rechecks relationship, restriction, consent, consent
  version, exact resource, age and expiry and records an allow or deny before
  returning data.
- Projection freshness is capped at 24 hours. Consent, relationship or
  restriction changes invalidate existing rows immediately, and the next read
  independently rechecks the live authority records so invalidation is not a
  cache of authorization.
- The student's bounded history shows actor, purpose, decision, returned field
  names, count and time, but no projection content. Guardian projections stay
  online-only under the offline classifier.
- This is repository evidence only. PostgreSQL 17 CI, preview migration,
  deployed publication, institution consent policy, legal/privacy approval,
  production identity verification and multi-cache revocation remain
  unverified and are not claimed.
