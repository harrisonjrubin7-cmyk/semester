## D-1066 · Keep four AI roles behind the same course policy and permission boundaries

**Decided 2026-10-01.** Executive Assistant, Executive Advisor, Tutor and Course Guide share one conversation service and institutional gateway, with distinct instructions and explicit tool allowlists. Course support uses a selected course; the institutional gateway checks approved source scope and latest published course rules before generation. Switching roles does not bypass course restrictions or confirmation requirements.

Role changes start a new conversation; history retains its role. Non-assistant roles do not inherit screen summaries or private standing preferences. Grade and attendance lookups are not in the role tool allowlists.

Application and NodeNext gateway typechecks, lint and production build passed. Focused suites passed 576 tests, with 48 live-provider tests skipped. The course-scope regression fails when its boundary is removed and passes when restored. Broad and shuffled tests encountered three missing external publication artifacts; visual verification was blocked for workspace localhost.

This is the four-role foundation. Section/assessment-specific enforcement, privacy-thresholded Course Pulse, the complete accessible-authoring workflow, Hermes installation and operational institutional activation are not completed by this decision. See docs/FOUR-ROLE-INTELLIGENCE.md.
