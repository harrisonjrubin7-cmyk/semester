## D-1156 · Modularize in place with enforced boundaries; extract services only on evidence

**Decided 2026-10-04.** Semester is reorganized into bounded domains inside the
existing deployable, not rebuilt and not split into services. Boundaries are
held by tests (`app/src/architecture/`): strict for new code, ratcheted for
legacy. The first vertical slice (identity, policy, tasks, calendar, Today) is
in `app/src/domains/`, composed in `app/src/composition/`, and held to the
legacy functions it wraps by parity tests.

This declines the earlier "clean-platform rebuild" and `services/`-per-domain
layout for now, for the reasons and with the extraction triggers in
[ADR 0011](../architecture/0011-modular-monolith-before-services.md) and
[0012](../architecture/0012-legacy-only-through-anti-corruption-layers.md). It
keeps that audit's domain list, launch discipline and completeness standard.
The plan, audit, retirement inventory and phases are in
[`docs/architecture/modularization/`](../architecture/modularization/README.md).

Related: [D-1144](D-1144.md), the server-side proposal for the same direction. This
is the client-side half, enforced and with a working slice; it takes no position
on the proposal's container-hosted `core` or `sync-gateway`.

Not done: no screen uses the new modules; no server route calls `decide()`;
no service has been extracted. Candidate deletions (61 files) and archives
(81 files) are proposals pending verification.
