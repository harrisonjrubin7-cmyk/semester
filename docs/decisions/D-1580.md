## D-1580 · Shared domain contracts live in `packages/domain-core`, and the registry stays in `packages/platform-control`

**Status:** proposed, pending the layout answer below.

**Context.** The continuation brief asks for a top-level `registry/`, `contracts/`, and `packages/policy/`. The repo already has a registry at `packages/platform-control/registry/`, validated by `npm run registry:validate`. A second top-level registry would give two sources of truth for capabilities and workflows.

**Decision taken in this PR.** The shared guards and types from the brief (grade release, payment states, degree scenarios, action items, AI answer frames, source labels) go in `packages/domain-core`, following the `packages/contract` shape. It is registered in the workspace alias map, `app/tsconfig.app.json`, and `app/vite.config.ts`, because `importboundaries.test.ts` requires it.

**Open decision.** Whether the brief's registry files (11 artifacts, listed as blocked in `docs/product/BUILD-COVERAGE.md`) go into `packages/platform-control/registry/` or into a new top-level `registry/`. Recommended: the existing registry. Nothing in the blocked set has been created.

**Consequences.** Blocked artifacts stay blocked until the answer is recorded here. Specs under `docs/` are not affected by the answer.
