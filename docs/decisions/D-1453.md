## D-1453 · The agent team is bounded contracts behind deterministic controls, built on platform-control

**Decided 11 October 2026.** The Semester Operator (`operator`) is
the agent team for the ecosystem and the company workflows. It records what
the first slice is and is not.

- An agent is a contract (prompt, task types, tools, allowed writes, limits,
  escalation), as data. Thirty-three of them, in the twelve suites the agent
  suite document named, with handoffs allowed only along that document's
  route table, within depth three and three proposals per result, and only
  when the operator enabled handoffs. A prompt grants nothing.
- Authority lives in application code, not in a model's judgement: a policy
  controller that fails closed and is frozen at start, approvals bound to the
  exact tool, target, payload hash, artifact hash, task, approver and expiry,
  a scheduler that deduplicates and joins on dependencies, limits a worker
  can only spend, and a redacted hash-chained audit log with a kill switch
  that interrupts running work and never repeats an uncertain external action.
- Scope is read from the platform-control registry, never restated. The
  coverage matrix has one row per registry record, its status derived from
  maturity evidence and operator tasks. Module agents are generated from the
  seventeen pilot release scopes.
- Development happens in a git worktree per task; checks run from an
  allowlisted argv without a shell and with a minimal environment.
- Model-backed task types run one model loop (`operator/src/runtime/agentloop.ts`):
  the model replies one JSON action per turn and never holds a tool; every
  request goes through the same policy gate, denials are fed back, limits
  are spent on every call, a worker's verdict is refused, and every message
  to the model is redacted. The loop is tested with a scripted model. The
  port speaks the Messages API over built-in `fetch`, no SDK dependency, and
  exists only when `SEMESTER_OPERATOR_MODEL_KEY` is set for the operator
  process; no key is configured or committed, so no live model has run. The
  Python runtime the supplied documents describe is not adopted.
- The demonstration registered the operator's policy controller as
  `control.operator-policy` in the registry; the run's records are committed
  under `operator/evidence/demo/`.

Not done: a live model run, a real deployment adapter behind the tested
release path, a sending adapter, approved operational connections, and a
database-backed store. Each is named in the
package README with the agent it unblocks.
