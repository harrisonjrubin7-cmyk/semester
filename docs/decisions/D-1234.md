## D-1234 · The keyboard-pass control is a gate: it fails the run when a planted fault goes unreported

**Decided 2026-10-04.** `app/scripts/keyboard-pass.mjs` plants seven faults under `CONTROL=1` and exits 3 unless every one is reported, so a clean run is distinguishable from a blind probe by the script itself and not by someone remembering to read the control's output. The probe also reads the browser's computed accessible name, separates a focus overlap that clears within 250 ms (`transient`) from one that persists, and adds SC 1.4.12 text-spacing and SC 2.5.3 label-in-name checks.

Why: the first run (#1204) produced two false candidates from the probe's own heuristics, and the old control had never detected its low-contrast plant (axe could not resolve its background), so it had said nothing about contrast. Both new checks were shown to go red with the check neutered; the first label-in-name version over-reported 34 against 0 because of whitespace, which the control did not catch and the re-run did.

Not decided here and not done: the script is not a CI step (it needs a browser and axe-core outside the repository; roadmap item 6); SC 1.4.13 and 3.3.8 / `autocomplete` are still unguarded; a clean run says nothing about contrast beyond what axe can resolve, and `npm run sweep:contrast` remains the guard for that; the seven newly clipped elements (A11Y-0009) are findings, not fixes.
