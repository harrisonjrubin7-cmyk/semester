## D-1228 · The institution gateway speaks its refusals and context through the platform package

**Decided 2026-10-04.** MIGRATION phase 1, first slice: `app/server/institution/gateway.ts` builds its error envelope with `PlatformError`/`errorResponse`, resolves correlation ids with `resolveCorrelationId`, and puts a platform `RequestContext` on every request (`AdapterContext.request`). The old envelope builder is kept verbatim in `envelope.test.ts` as the golden it is compared against; the platform's catalogue was aligned with the live wire rather than the wire with the catalogue (`outcome_uncertain`, `refused`, 405/410/413/415, domain-specific codes carried by `PlatformError.specific`).

Two behaviours change on purpose: a client `X-Tenant-Id` that disagrees with the session is refused, and an identity whose ids fall outside the platform's id alphabet is refused rather than passed through.

Not done: `lib/university.ts` on the SDK, the edge functions' envelope, real tenant status and verification kind in the context, and a check against production tenant ids, which only someone with the real data can make.
