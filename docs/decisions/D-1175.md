## D-1175 · Domain APIs are idempotent commands, decided by the policy point, written by one atomic commit

**Decided 2026-10-04.** Every domain API takes writes as commands that carry a client-minted id, are decided inside the transaction by `decide()`, and commit record, idempotency ledger row, audit row and outbox event together; reads of anyone else's data are audited before they are served. Tasks and calendar are the first, in `app/server/productivity/`; the conventions and the plans for the other twelve domains are in [`docs/API-PLATFORM.md`](../API-PLATFORM.md).

Storage is one `security definer` commit function with compare-and-swap on each entity's sequence number, so a service that cannot hold a transaction across a request still cannot interleave. Offline replay is why the command endpoint is a batch and the ledger keeps 35 days; both differ from the #1144 proposal (P-13), and the doc says where.

Not decided and not done: nothing is mounted; the Postgres adapter, authenticator and route are unwritten; the new tables are not yet registered with account-link, export and erasure; the outbox has no retry delay; files, webhooks and the other domains are specified only; whether to backfill and retire `public.tasks` is the owner's. Legal conclusions stay with counsel.
