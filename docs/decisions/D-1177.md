## D-1177 · A connector augments a native capability and is safe to turn off, and the framework pieces that were missing are libraries first

**Decided 2026-10-04.** Every provider domain must name the native Semester capability it augments and the native screen that still does the job with the connector off; a connector is never the only way a capability works. This is enforced by types (`NATIVE_FALLBACK` is exhaustive over `ProviderDomain`), by a test against the real screen table, by the degraded experience always returning the native route, and by a `disable_safe` check in the contract harness that every live adapter must pass. See [`INTEGRATION-CONTROL-PLANE.md`](../INTEGRATION-CONTROL-PLANE.md).

The parts the control plane lacked were added as pure, tested libraries beside the existing pipeline, not as a second control plane: credential leases, the OAuth/OIDC token lifecycle, webhook ingress, a per-connection rate guard with a circuit breaker, a health model with reasons, a parallel-run assessor with a cutover gate, and the conformance harness. Choices worth keeping:

- A dead OAuth grant is never retried; the connection stops and asks for reauthorization.
- Only retryable provider failures open the breaker. A permanent failure is a fault in our configuration and must not hide behind "provider unavailable".
- A credential lease is audited before it is issued, and no audit record means no lease.
- A cutover is requested on evidence plus two independent sign-offs in different roles, never by the proposer, and the assessor never performs it.
- "Needs reauthorization" is a reason under `error`, not a new connection status, so the database vocabulary is unchanged.

The guard, lease broker and token manager are wired into the tick and worker through a per-pull `ProviderClient` passed as `pull(request, client)`. The tick and worker define the ports they need (`ProviderRuntime`, `FailureClassifier`) and the Edge Function composes `providerRuntime()` from `provider-client.ts`, because the import-boundary ratchet (`importboundaries.ts`) lets the gateway shrink its imports of client source but not grow them; moving the shared code into `packages/` would have needed a new workspace package, a lockfile change and an Edge-generator change, and is the integration domain's wave C4. The worker classifies a failed pull (`authentication` dead-letters at once, `rate_limit` carries the provider's wait) instead of calling every one an outage. The wiring **fails closed**: an adapter that declares a credential, run with no credential services, never calls its provider. The contract harness fails an adapter that makes a call round the client or leaks the credential it was handed.

Not decided here and not done: no live adapter is registered and no provider endpoint has been exercised; production has no secret backend, token store or lease audit sink, so every credentialed adapter is refused until they exist (the next piece of work, needing storage this does not create); the breaker and Retry-After wait are per pull and do not persist across ticks, which needs a column on the connection; there is no webhook HTTP route; `connectionHealth` is not fed from stored rows; email is a student-credential capability and reporting is not modelled, and making either a tenant connector needs a catalog-domain migration and a data-class decision; every contractual and legal conclusion (data-sharing agreements, FERPA school-official designations, vendor terms) stays with qualified counsel.
