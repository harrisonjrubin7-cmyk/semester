# D-1298 — Probe every owner-keyed table; do not build the free-text scanner

Status: decided under the founder's delegated authority (stream 01, slice 2).

## Context
Slice 1's sweep (D-1294) left eight tables inconclusive because each needs related rows before its owner can read it. The stream 01 report also called a free-text redaction scan the largest gap against "AI never receives student records".

## Decisions
1. **Fixtures, not exemptions.** Each of the eight tables gets a `fixtures` entry in the suite (a value its rules accept, a parent group, an adult enrolled student). All 64 readable owner-keyed tables are now probed; the floor is 64 and can only rise.
2. **No new company-role reads were found.** The exception list is unchanged.
3. **The free-text scanner is not built.** `packages/institution/src/ai-data-class.ts` is a deliberate design: a declared-field-class ceiling (T2), unclassified = T3, "names not contents", and it states it does not read free text. A content scanner would be heuristic, would give false assurance, and would contradict that design. The earlier "largest gap" claim in the report and the diff (row "lib/ai/redact.ts", `ai_policy.student_id_pattern`) is withdrawn. Revisit only if the AI provider terms (human-only, BUILD.md §7) leave free text reaching a provider.

## Consequences
Owner columns other than `user_id`/`student_id` remain unswept (P2). `community_volunteers/trust_safety_reviewer` still awaits the privacy owner.
