## D-1053 · The executive-assistant layer starts as pure modules; Today, Grades and Registration take the first wiring

**Decided 1 October 2026.**

Three specs for an academic executive assistant were checked against `origin/main` before anything was written. Most of what they describe already exists (recovery, changes, what-if, the Today decision surface, registration day, no-wrong-door routing). What was absent is added as pure modules with tests in `app/src/lib/`:

- `triage.ts` (seven assignment states, private queue order), `deadline-groups.ts` (the five horizons), `outcome-scenarios.ts` (fixed-average scenarios, required-score line)
- `guide-bar.ts` and `calm-controls.ts` (the Semester Guide model, snooze, and the student's calm settings)
- `weekly-reset.ts` (five-step skippable reset; reflection private by default), `plan-recovery.ts` (original plan kept as Scenario A, only `confirm` returns a changed plan), `goal-plan.ts`
- `semester-packets.ts`, `decision-compare.ts` (no winner field, unknown cells say so), `ask-human.ts`, and `calm-language.test.ts` (banned-phrase guard)

Wired: the Guide on Today (`TodayGuide`), Course Outcome Scenarios on Grades (closed until opened; refuses on incomplete weights).

**Registration Mode now shows 72 hours out, not 7 days.** This reverses the window in `docs/REGISTRATION-DAY-MODE.md`, because the spec asks for 72 hours. A window further out is still reachable by turning the mode on.

- A scenario is refused, not warned about, when weights do not total 100, nothing is scored, or nothing is left.
- The queue's weighting is private and returns an order, never a number; Today's action cards still show their score parts (`actions.ts`). Reconciling the two is open.
- `queue()` ranks but the equity gate matches on function names and does not see it. It needs an owner decision on review before a screen uses it.
- Two new device stores are named in the backup coverage test as exempt: `semester.guide-choices.v1` (an expiring display marker) and `semester.calm.v1` (the student's settings, a candidate for the backup).

**Wired to screens:** the Guide on Today; the deadline horizon, assignment states, Weekly Reset, weekly reflection and goal planner on Today's *This week* tab; the Guide settings under Alerts; ask-a-human on Help; Course Outcome Scenarios on Grades.

**Built and tested, not mounted:** `RecoveryMode` (nothing yet detects a plan-breaking event to open it), `PacketPreview` (no packet source feeds it) and `DecisionTable` (no screen assembles the option facts). Each needs a data source decided before it has anywhere honest to appear.

**Settled on 1 October 2026, at the owner's instruction:**

- **`queue()` is `orderQueue()` and has an equity review.** Renamed so the equity gate's name list sees it, and reviewed in `lib/equity/reviews.ts` and `docs/EQUITY-REVIEW.md`. The review was written from the code's actual inputs and is not independent (`INDEPENDENT` stays `false`). It names one open finding, O-1: the source-label term tilts toward institution-verified dates, the same shape as A-1. It found a second gap (the list never said why one item sits above another), and that was fixed in the component, so it is not listed.
- **Weekly-reset and calm-settings stores are in the workspace backup**, as device-scoped records. Reflection answers and assistant memory are the student's to read and clear, so the file carries the picks and the settings and none of them, and a restore keeps what the device already holds and never invents any (the advisor-meeting notes precedent). Both are tested through the real backup, and both guards were broken to check they fail.
- **The "When you are behind" screen is now "Catching up"** (short form "Catch up"), in the navigation, the page header and the soft-shell hero. Its route id stays `behind` so links and bookmarks keep working, and its search keywords still include "behind", "late", "overdue" and "catch up". The allowlist entries for it were removed from the language guard. **Not renamed:** capability register entry CAP-006, "When You Are Behind", which mirrors the supplied requirement and is never shown to a student; the rollout documents generated from it and their traceability links use that name. It stays on the allowlist with that reason. Historical audit documents that quote the old label were left as written.

**Not done:** assignment effort and saved work blocks are not recorded for course items, so the assignment states list shows only what the syllabus dates support (mostly "ready" or "needs review"); accepted study blocks in Weekly Reset live in component state only; the weekly-reset and calm stores are keyed per device, not per account. The Guide's next step and the briefing below it can say the same thing on Today.
