## D-1157 · The COO operating system is proposed, not in force, and every service level starts as a target

**Decided 4 Oct 2026.** `docs/operations/coo/` adds the operating layer the
existing pages lacked: cadence, implementation method, RACI, support model,
incident and continuity operations, readiness scoring, templates, handoffs,
blueprints and a founder-to-team plan.

- **Proposed, not operated.** Each page says so in its control table. A
  template existing is not evidence a process runs.
- **Service-level ladder.** Designed, measured, staffed, committed. Every
  number starts at the first rung; only counsel-approved contract language and a
  claims-register entry reach the last. No page promises coverage, response
  times or uptime.
- **The council still decides.** The tenant readiness score is planning input;
  `decide()` in `launchreadiness.ts` remains the only way to reach GO.
- **Marketplace stays dormant past a referral directory.** Nothing here moves
  money (D-146); a payments phase needs a new owner decision and counsel.
- **Guarded.** `app/src/lib/ops/coo.test.ts` holds links, anchors, control
  rows, one accountable seat per RACI row and every defined ID. Five injected
  defects each turned it red.

**Not decided here:** staffed hours and channels; who accepts the vacant
security, trust, data and finance seats; real RTO and RPO; on-call
compensation; whether any page becomes an authoritative entry in
`SEMESTER-OPERATING-SYSTEM.md` (a separate change through `operatingsystem.ts`
and `npm run registers`).
