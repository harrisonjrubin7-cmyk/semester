## D-1143 · The offline store is built web-first, extending `main`, and refuses official data instead of encrypting it

**Decided 4 October 2026.**

Three decisions, one change (`app/src/lib/vault/`, `docs/architecture/rebuild-slice-audit.md`):

1. **Extend `main`; do not restructure into `apps/ services/ packages/`.** Identity, tenancy, the policy decision point, ledger chains and seals, and the integration control plane already exist, so the brief's first slice was mostly built. A greenfield monorepo would discard the tests that are most of the evidence.
2. **Web vault first, native SQLCipher later.** SQLCipher needs an iOS/Android client this repository does not have. The web half fixes the classification gate, record format and queue semantics the native client must also honor. It is software-keyed: it defends a copied profile or leftover disk, not script in the page.
3. **Refuse, do not encrypt, official classes.** Grades, billing, protected-case, raw-source, guardian and credential data are never kept offline; an encrypted copy is still a second record to expire, wipe and reconcile.

**Not done.** No screen uses the vault; moving tasks and drafts onto it needs a `localStorage` migration with a restore path. Native SQLCipher, hardware key wrapping and any CRDT runtime remain unbuilt. Public wording and the 14-day assignment-metadata cache are with counsel.
