## D-1255 · Tools and the edit form stay on dispatch; Today is not flipped until it has a read model

**Decided 2026-10-04.** Three things were left after [D-1149](D-1149.md) put task writes behind
`VITE_DOMAIN_TASKS`. Each was looked at rather than ported, and none is built.

**`lib/tools.ts` stays on `dispatch`.** The assistant's tools return an `Action` as data, with an
`undo` that is either the inverse `Action` or a way to find the row that appeared. `ai/converse.ts`
applies it with `dispatch(p.action)` and keeps the inverse for the undo. Routing that through the
tasks domain would rewrite the assistant's propose, confirm and undo ledger, which is a different
system with its own contract, and `lib/` sits below `composition/`, so it could not import it.

**Mine's edit form stays on `dispatch`.** One `editTask` patch carries the title, the day, the time,
the repeat rule and the steps. The domain owns none of the last two (repetition is `lib/repeat`'s, by
D-1149), and sending the day through the domain would turn a form edit, which has no undo, into a
`moveTask`, which does. That is a change to what a student sees, made to move a call site.

**Today is not flipped, and no `domainToday` flag exists.** The Today shadow was measured, which is
what [03-refactoring-sequence.md](../architecture/modularization/03-refactoring-sequence.md) asks for
before a flip. In a real browser, with `VITE_TODAY_ACTION_CENTER=production` and
`VITE_TODAY_SHADOW=on`, on six seeded states: nothing of the student's; overdue, today, soon,
someday and done tasks; three timed tasks; a repeating task due today; appointments today and
tomorrow; tasks with an appointment. All six report "agrees with the Action Center" and none an
unexplained difference. The control: with the domain's `dueToday` emptied, the four states that have
a task due today each report `day, legacy only: task:<id>` for the missing tasks, and the two that do
not still agree. The probe sees a disagreement.

That is evidence for one day. Trying the flip found it is blocked on a read model:

- `TodayActionCenter` builds its rows over `HORIZON_DAYS = 10` and feeds `planCommitments`;
  `today.view()` reads one day (`agenda(on)`).
- The view's `schedule` is what is left (`filter(e => !e.done)`); the screen keeps finished
  deadlines struck through and counts them, so "Due today" and "Yours today" cannot read it as it is.
- The ranking is `lib/actions.rank`, borrowed whole by `legacyRanking`, so reading it from the domain
  changes where it is computed and nothing a student sees, for an asynchronous first paint.

Whoever takes phase 3 should decide the first two, a multi-day horizon and whether the view keeps
finished entries, before touching `Today.tsx`. Nothing here forecloses either.

Not done: the dogfood week with `VITE_DOMAIN_TASKS=production` has not started. It needs the
repository variable set on a Pages build; the check is whether the console ever logs a
`[domainTasks]` fallback line.
