## D-1481 · The saga's crash rehearsals run the real runner through the real adapter against a migrated database, and nowhere else

**Decided 12 Oct 2026**, continuing C-6 on the owner's instruction. Follows [D-1361](D-1361.md) (the store) and [D-1479](D-1479.md) (the adapter).

- **What was decided.** `app/server/institution/postgres-access-saga.integration.test.ts` drives `AccessSagaRunner` over `PostgresAccessSagaStore` against the database `supabase/check.sh` builds, reached through `psql` as `service_role` as the productivity adapter's test already does. `supabase/adapter.sh` runs both adapter suites. The file skips without `SEMESTER_PG_HOST`, so an ordinary `npm test` run neither needs a database nor pretends to have used one.
- **Why not a fake that loses leases.** The unit tests' `FakeStore` never expires a lease, never fences a token and never races, so a rehearsal there would prove the fake. What the rehearsals exist to hold lives in the SQL: the lease expiry in `access_saga_claim`, the token and revision check in `access_saga_save`, the dedupe in `access_saga_wake`. Only the real functions can fail them.
- **The crash is a process, not an exception.** A `DyingStore` throws from `save` and then refuses to `release`, because a dead worker releases nothing. That is what makes the successor wait for expiry and what leaves a stale token for the fencing rehearsal. A store that threw but still released would rehearse a storage error, which the runner's own tests already cover.
- **The operation key is the crash's recovery.** The successor prepares under the key the dead worker used, and the rehearsal checks the keys are equal and the grant found is the one that key names. That is the whole argument for a grant prepared before a crash not being minted twice; the participant's idempotency is assumed, the key reaching it is now shown.
- **Held by.** 28 tests across both adapter suites. Two mutations run and both red: no lease release in the runner fails five rehearsals; a claim that takes over an unexpired lease fails the crash and the race rehearsals. On local Postgres 16 with `SEMESTER_CHECK_PG_ANY=1`; the project runs 17, and `adapter.sh` says so on every such run.
- **Not done.** No worker or route runs the runner in production. The revocation barrier at a real enforcement point, which only a real administrator and enforcement point can show.
