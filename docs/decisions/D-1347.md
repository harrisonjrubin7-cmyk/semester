## D-1347 · "Who can see your things" is a read over the five existing sharing tables, with no new table and no names

**Decided 2026-10-06**, by the assistant under the executive authority the founder delegated in-session (D-1287). The founder, or the privacy owner, can overrule it.

**Context.** Stream 02 asks for a single "who has access to me" view. Five features already let a student open a door (support access windows, advisor shares, athletic support shares, family grants, school-recorded guardian links), each with its own screen to end it and its own check suite. Checking main first: nothing aggregates them.

**Decisions.**
1. The view reads the five tables for the signed-in student and adds no table, function or migration. Each already has a student-side read policy, and every read also asks for `student_id = me`, so a policy that later widens cannot pull another person's row in.
2. It shows what is visible, when it ends and which screen ends it, and no person's name. None of the five screens names the other person today, and adding names is a privacy decision, not a display one.
3. A source that cannot be read is reported as unknown, never as empty. A family grant nobody accepted and a guardian link recorded with no rights are not access and are not listed.
4. It is a panel on Your data, not a settings page, because the settings index is capped at eleven rows.

**Consequences.** Ending access stays where it was made. Whether to show names, or to end access from the list itself, is open for the privacy owner. The sessions table, per-session sign-out and account switcher remain the last stream 02 slice, and need a migration and a check suite.
