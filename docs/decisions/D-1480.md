## D-1480 · Port only the semester-core modules that have no repository counterpart

**Decided 2026-10-11.** On PR #1480, the handoff `semester-core/` package is ported in slices. The first slice takes `consequence`, `freshness` and `approvals` into `app/src/lib/core/`. `access`, `aigateway`, `provenance` and `nextaction` are not ported in this slice.

Why: BUILD.md says never stand up a second core. `access.ts` would be a second permission model next to `has_capability`. `aigateway.ts` must reconcile with the live gateway in `app/src/ai` and `app/server` before anything else calls it. `provenance.ts` and `nextaction.ts` conflict with the repository's `provenance.ts`; `nextaction` depends on the handoff version of it.

What this means for later slices: `access` maps onto the repository's capability model or is dropped. `provenance` and `nextaction` are reconciled against the repository's file, and their names stay the repository's. `aigateway` is reconciled with the live gateway before any screen calls it.
