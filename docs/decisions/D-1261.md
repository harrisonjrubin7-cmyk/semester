## D-1261 · The Action Center's commitment rows can come from the domain, behind `VITE_DOMAIN_TODAY`

**Decided 2026-10-04.** With `VITE_DOMAIN_TODAY=production` the Action Center draws its
"coming up" rows from `src/domains/today` instead of building them inline. Every other state
draws the screen's own rows, as before. This is phase 3 of
[03-refactoring-sequence.md](../architecture/modularization/03-refactoring-sequence.md) for
those rows, and it answers the two questions [D-1255](D-1255.md) left open.

**A look-ahead, not a longer day.** `today.commitments(days)` reads N days from the calendar
slice, today first, up to 31. The day's own read model is unchanged. A task source (`tasksOn`
plus `readDue`) joins the sources for the look-ahead only, because `today.view()` reads tasks
from the tasks slice and would count each one twice.

**Finished entries are kept, marked `done`.** The look-ahead keeps a ticked deadline and a done
task; `today.view()` still drops them. Nothing that reads the view changes, and whether a
finished entry is drawn is the screen's call.

**The rows are the legacy rows, joined to legacy records.** An entry says what is on which day
and when. A row also says what to call it (the course code, the place, how far to trust the
date), which is the legacy record's business, so `composition/commitments.ts` joins the two.
It returns `null`, not a shorter list, when an entry has no record behind it.

**The screen draws the domain's rows only while they are loaded, current and complete.** An
answer still being fetched, built from older state, or incomplete is replaced by the screen's
own rows. So a late or stale answer costs nothing a student can see. `preview` and `sandbox`
draw the screen's rows and say in the console where the domain's differ, once per distinct
finding.

Held by:

- `composition/commitments.test.ts`: 16 cases, four states at four pinned moments on the shipped
  seed. Every legacy row is present; anything extra is already past and discarded by
  `planCommitments`; `planCommitments`, which is what is drawn, gives the same answer. Six
  mutations of the mapping each turn the cases red.
- `composition/commitmentrows.test.tsx`: the policy as pure functions, and a real mounted store:
  off never draws the domain; production does, once loaded, and never an answer built before a
  change; preview reports a real disagreement once and a repeated one not at all. Five mutations
  of the hook, and the dedupe, each turn named tests red.
- A real browser, five seeded states (nothing of the student's; tasks across the ten days;
  appointments with places; a repeating task and appointment; everything together), three builds:
  flag off, `production`, `preview`. The Action Center's text is identical in all three, and
  `preview` reported no ten-day difference. The control, with the domain's look-ahead missing its
  tasks: the `production` screen changes in exactly the three states that have tasks, and
  `preview` leaves the screen alone and reports it in those same three.

Not done: only the commitment rows moved. "Due today" and "Yours today" on the Today feed, the
all-clear line, and the Action Center's own ranking still read the legacy selectors (the ranking
is `lib/actions.rank` borrowed whole, so moving where it is computed would change nothing a
student sees). The legacy row builder, `lib/commitment-rows.ts`, stays one release as the
fallback and the other side of the parity test; `screens/Today.tsx` is not locked in
`legacy.json`. Nothing has run at `production` outside tests and a local browser: the next step
is a week of the flag on in a dogfood build, watching the console for `[domainToday]`.
