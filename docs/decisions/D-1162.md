## D-1162 · Offline and sync run through one policy table and one queue, and official records are denied offline by default

**Decided 2026-10-04.** The reference core is [`packages/offline-sync`](../../packages/offline-sync) and the design is [`docs/architecture/mobile-offline-reference.md`](../architecture/mobile-offline-reference.md). It follows D-1144's P-07 (Capacitor shell, SQLCipher plugin, 30-day go/no-go spike) and P-08 (store port, command queue, Yjs for text) and does not replace them.

- Every offline workflow is shown as `local`, `pending`, `synced`, `rejected` or `conflicted`, derived from the contract's queue phases. `synced` only after a server acknowledgement.
- One data-class table (`policy.ts`) decides what may be cached, queued, held for a tap, or never queued. Registration, grades, money, permissions, consent, approvals and record amendments are never queued; the gateway refuses them even if a client sends them.
- Where the audit's table allows a grade read cache and the repository contract says "denied by default", the contract wins: official classes cache only on tenant opt-in, as an expiring read, and a tenant may shorten a limit but not lengthen it.
- An idempotency key means one command. The server remembers applied keys only; a changed command gets a new key.
- Same-field conflicts are settled by a server-clamped hybrid clock only for classes where a loss is cheap to see and undo (tasks, plans). A person's writing asks. CRDTs are limited to shared authored text and its annotations.

Not decided and not done: the Capacitor choice remains a recommendation until the P-07 spike passes; lease defaults (7/30/90 days, 5-minute idle) are proposals; no native shell, SQLCipher binding, gateway endpoint, migration or CRDT service exists; `cloud.ts` and `lib/sync` are not on the engine; the capability registry rows stay Absent. Legal conclusions (biometric statutes, FERPA on personal devices, SQLCipher licence, export classification, receipt retention) stay with qualified counsel.
