## D-1274 · Make the existing token pipeline enforceable for agents and CI, with a ratcheting raw-value ledger and Figma as a read-only input

**Decided 2026-10-05.** `look.ts` → `tokens.css` → `tokenexport.ts` → `semester.tokens.json` stays the only token pipeline; the JSON is generated and never edited, and `CLAUDE.md` now says so with the order in which files win. Raw colour functions, z-index, shadow, TSX radius, duration and easing, and CSS spacing and type are counted per file against `app/src/styles/rawbudget.ts` by `npm run design-system:audit`: the ledger may shrink and may not grow, in the shape `budget.ts` already has. The 330 values already in the tree (50 files) are recorded, not fixed. A custom-property definition is a token being decided and is not counted; quoted hex in `.tsx` stays `hex.test.ts`'s. `tokens:check` runs the existing `tokenexport.test.ts` and builds no export of its own. CI runs `design-system:check` and uploads the report, with no credentials.

Figma is an input for approved visual intent, read through the remote MCP server named in `.mcp.json` (no credential; each developer signs in with `/mcp`). Mappings live in `docs/design-system/figma-mapping.json` and must resolve to a token in the export and a pattern that exists; the shipped manifest is an empty template because no Figma file is connected. No Figma write is automated.

Not decided here and not done: fixing the ledgered values; connecting a real Figma file or setting `requiredTokens`; Code Connect; visual regression in CI; correcting the 760/1180 breakpoints in `docs/design/GOVERNANCE.md` (`lib/media.ts` says 600/840/1200/1600). Tailwind, Storybook, pnpm and a `packages/ui` or `packages/tokens` were considered from the strategy document and rejected: none exists here and each would be a second source of truth.
