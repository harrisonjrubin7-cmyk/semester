## D-1249 · "Mounted" means naming what a producer exports, and a type declaration is not an emitted event

**Decided 4 October 2026.**

Eight docs-consistency tests on `main` were failing, each because documentation lagged merged code (`app/src/lib/docs`, PR #1249). Two of the fixes changed what a guard means, and that is the part worth recording:

1. **A producer is mounted only if something imports its package and names one of its exports.** The docs generator and the `examples` guard treated any import of `packages/platform` as mounting the producers inside it. The institution gateway now imports that package for its error envelope, correlation ids and request context, so the old rule would have printed "producers are mounted" into a generated page, which is false. The `examples` guard now says the productivity service is imported by nothing and the platform package has exactly three importers, none reaching `eventFromContext` or `TenantOutbox`. A new importer fails the guard and has to say what for.
2. **A telemetry event counts only where it is emitted.** The scan matched `event: 'credential.leased' | …` in a type declaration (`VaultAuditEvent`). It now counts object-literal properties only. The vault's audit event is therefore not listed under "Sent to a server today"; whether it should be is left to the owner.

**Not done.** `architecture.test.ts` (`lib/governance/eval-lint.ts → community/pii.ts`, an upward import from #1166) also fails on `main`. It is a design decision (move the PII detector down or invert it through a port), and `legacy.json` may only shrink, so no exception was added. No documentation page was reviewed for accuracy beyond what the failing tests check.
