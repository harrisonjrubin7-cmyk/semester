## D-1149 · Task writes go through the tasks domain, behind `VITE_DOMAIN_TASKS`

**Decided 2026-10-04.** Adding, ticking, moving and deleting a task go through
`app/src/domains/tasks` when a build sets `VITE_DOMAIN_TASKS=production`; every
other state is the legacy reducer, dispatch for dispatch. This is phase 4 of
[`modularization/03-refactoring-sequence.md`](../architecture/modularization/03-refactoring-sequence.md)
for the tasks slice, under [D-1156](D-1156.md), and it is built on that slice
rather than beside it.

What moved: thirteen screens and components stopped dispatching `addTask`,
`toggleTask`, `moveTask`, `editTask` and `deleteTask` themselves. They ask
`useTaskActions()` (`app/src/state/taskactions.ts`) for `add`, `toggle`,
`reschedule` and `remove`. With the flag off that is the same dispatch as
before. At `production` it is the tasks use cases (`addTask`, `toggleTask`,
`rescheduleTask`, `removeTask`) through the composition root, which still ends
in the reducer, so persistence, sync and the unpushed-edits flag see every write.

Four decisions inside it:

- **A move is `moveTask`, a delete is `deleteTask`.** The undo table
  (`lib/undo.ts`) names those actions, and a move that went out as `editTask`
  lost its "Action moved" toast. A new day is `moveTask`; `editTask` is left for
  sending a task back to "someday" and for a time on its own. The one call site
  that sent `editTask` on main (the month day-shift button) now offers the undo
  too, on both paths alike.
- **It never loses an action.** A domain refusal or exception falls back to the
  legacy dispatch and is said once in the console. Only a task that has gone
  between the draw and the press is skipped.
- **Every write waits for the store to commit** before the next press reads it.
  Two quick ticks otherwise both read the old list and land on the wrong side.
- **The domain does not add a task with a repeat rule or steps**; the legacy
  reducer does, because the domain's `NewTask` carries neither.

Not done: Today's "Due today" list is not cut over, and there is no
`domainToday` flag. Main's Today read model drops finished deadlines
(`schedule` is what is *left*) where the screen keeps them struck through and
counts them, and its `view()` is asynchronous only; flipping the list means
deciding both, which is phase 3. The Mine edit form (`editTask` with steps and
repeat) and `lib/tools.ts` still dispatch directly. Nothing has run at
`production` outside tests and a local browser; the next step is a week of the
flag on in a dogfood build.
