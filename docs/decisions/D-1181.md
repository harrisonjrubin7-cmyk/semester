## D-1181 · Record the data architecture as a proposal set: registry first, additive, nothing applied

**Decided 2026-10-04 (proposal status: the owner accepts each proposal separately).** The data-layer reference is
[`docs/architecture/data-architecture/`](../architecture/data-architecture/README.md). It keeps the existing
direction (Postgres with RLS, the outbox, local-first student data, source-system-only write authority) and adds a
per-table registry with a conformance view, a precedence rule held as data, an outbox sweep, a search index and AI
retrieval whose security filter is row-level security evaluated as the caller, an analytics boundary with a floor of
ten for institution-readable figures, and guards for hold coverage and cross-tenant references.

Chosen over a rewrite of the schema (the 171 migrations and their check suites are the most valuable correctness asset),
over a separate warehouse (nothing measured justifies one), and over a service_role AI retriever (a bypass).

Not decided and not done: no migration, flag or code changed; the twelve SQL files are proposals, validated on
PostgreSQL 16 against a database built from all 171 migrations (the project pins 17) with 53 mutations each turning
its test red. Every **counsel** item (directory information, retention minimums, the T4 conflicts for accommodations
and aid), the future of the shared-key AI function, whether `imported` ranks as institutional or user, and D-124's
choice not to keep a deletion ledger are left to people; this record does not reopen D-124. `FORCE ROW LEVEL SECURITY`
and `app.tenant_id` (the CTO pack, D-1144) need the touch-point checks in the README before they land.
