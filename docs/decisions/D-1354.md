## D-1354 · Where you are signed in is two functions over GoTrue's session table, and the account switcher is not built

**Decided 2026-10-06**, by the assistant under the executive authority the founder delegated in-session (D-1287). The founder, or the privacy owner, can overrule it.

**Context.** Stream 02 asks for a sessions list, per-session sign-out and an account switcher. The earlier audit (D-1342's table) said the list needed a sessions table with RLS. Checking main first, nothing existed for it, and checking production's `auth.sessions` columns showed the table GoTrue already keeps holds everything needed; school offboarding already deletes from it inside a definer function.

**Decisions.**
1. No new table. `my_sessions()` and `end_my_session(want)` are definer functions that read `auth.uid()`, take no user id, and touch only the caller's own rows. The audit's "needs a table" was wrong and is corrected.
2. The address a session came from is not returned. A student can tell a laptop from a phone by browser and system, and an address is somebody's whereabouts.
3. Ending a session stops that device renewing; the access token it holds lives until it expires, at most an hour. The screen says "within the hour", not "now", because saying "now" would be untrue.
4. The session making the call cannot end itself through this path (that is signing out). Anyone else's session reads as "no such session", the same as a missing one, so the function does not confirm another account's session ids exist.
5. The account switcher is not built. Supabase holds one session per browser client; switching accounts means keeping several sessions side by side, which changes how sign-in and sign-out work for everyone. That is an architecture decision for the product owner, not a slice of this one.

**Consequences.** The migration is not applied to production; merging applies it through Supabase Branching and needs owner approval. Open for the owner: whether the account switcher is wanted for the pilot at all (a student with two Semester accounts is rare), and whether the token lifetime should be shortened for school accounts so that "within the hour" becomes sooner.
