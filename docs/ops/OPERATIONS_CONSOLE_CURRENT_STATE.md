## 5. Approval and break-glass flow as built

1. `request_approval(duty, tenant, target, detail, evidence, ticket, correlation)`.
   Requires the requester party for the duty, evidence and ticket; break-glass
   additionally needs `breakglass:request`. Audit is written first.
2. `decide_approval(request, decision)`. Needs fresh MFA (aal2, 15 minutes).
   Self-approval refused, primary key blocks a double approval, two-person
   duties count distinct approvers, and an overdue break-glass review blocks the
   approver.
3. `console_act(request, correlation)`. `console:operate` plus fresh MFA plus
   requester-or-approver. **Fail-closed:** audit write, then effect, then mark
   `executed`. If the audit insert is revoked, no effect happens (proved in
   `console-approvals.check.sql`).
4. Break-glass: expiry check constraint at most 4 hours, `review_due` after
   expiry, `close_break_glass` by subject, `review_break_glass` by a security or
   founder seat that is not the subject.

Gap against the brief: break-glass **expiry is enforced at read time**
(`has_capability` checks `expires_at`), which is sound, but there is no job that
flags a grant as expired or that raises an overdue review except at
`decide_approval` time and in the command center queue.

`governance_incident_notices`), **SLO/SLI/error-budget tables**, **access review
or attestation**, **tenant health** (only per-billing-account

**watermarks/checkpoints/cursors**, an **outbox publisher worker**, an **outbox

error-budgets.ts` (budget state, burn rate), `incident-comms.ts`,
`consolechecks.ts`, `projections.ts` (claim projections, unrelated to read
models), `deal-desk.ts`, `named-tenant-approval.ts`. Those are reusable inputs,
not wired features.

  are platform-wide by design; a scope test is meaningful only for the new read
  models.
- No test that `my_capabilities()` agrees with `has_capability` under
  break-glass.
- No test that the browser cannot write the high-risk tables listed as
  finding F-1 in the exposure classification without going through an approval.
- No test of a read RPC refusing with a forbidden error versus returning empty.
- Tests are `DO`-block SQL checks run by `supabase/check.sh` (no pgTAP). Frontend
  tests are vitest.
