# Semester software engineering syllabus
Status: proposed 16-week curriculum; synthetic exercises only. This additive preview does not replace course-engine or workflow-lab. Prerequisites: basic programming, Git and introductory web concepts. Suggested weekly effort: two class sessions and 4-6 independent hours.

Outcomes: define contracts; enforce authorization and tenant isolation; build accessible workflows; preserve audit and provenance; operate retry-safe events; design typed SDKs; reconcile pilots; defend evidence-backed decisions.

Assessment: weekly labs 40%, midterm architecture review 15%, capstone 35%, peer review/reflection 10%. Weekly rubric: correctness 30, tests 25, security/privacy 20, maintainability 15, documentation/reflection 10. Automated visible tests only inform correctness. Instructor publishes final grades and handles accommodations, appeals and permitted AI assistance. Security defects block deployment, not automatically determine academic penalties.

Every week: implement the contract drill; add three boundary tests; integrate the topic into the synthetic planning-extension capstone; submit code, test evidence, DESIGN.md and 150-250 word reflection. Python drills are not complete full-stack labs. TypeScript capstone must use runtime validation, explicit environments and no browser secrets. Real student records and credentials must never enter exercises or AI.

Weekly topics: 1 system boundaries; 2 Git/evidence; 3 validation; 4 pagination; 5 authorization; 6 tenant isolation; 7 transactions/audit; 8 accessibility; 9 idempotency; 10 events; 11 diagnostics; 12 SDK retries; 13 webhook security; 14 release evidence; 15 reconciliation; 16 activation/defense. Week 3 explicitly rejects unknown fields and non-dictionaries. Instructor sets dates and late/resubmission policy before offering the course.
