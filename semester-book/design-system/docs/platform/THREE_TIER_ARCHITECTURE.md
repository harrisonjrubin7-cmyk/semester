# Three-tier architecture and strategic borrowing

_Semester platform maturity program · 2026-10-05 · Source: uploads/Apple vs Google vs Microsoft in EdTech_ build a st.pdf._

Sell the unified Education OS, deploy a focused pilot, expand as a trusted institutional platform, and mature into an open ecosystem where students, institutions, developers, employers and partners all gain from the same connected graph.

## Tier 1 · Experience platform

Apple-like: calm, clear, fast, accessible, coherent.

- Student OS
- Faculty Course Studio
- Advisor workspace
- Registrar tools
- Campus services
- Family portal
- Career/alumni
- Company site
- Operations console

## Tier 2 · Education intelligence platform

Google-like: data, search, AI, source authority and recommendations working together.

- Identity graph
- Education graph
- Search
- AI gateway
- Policy engine
- Workflow engine
- Evidence/provenance
- Analytics
- Recommendations
- Outcome models
- AI evaluation
- Human escalation

## Tier 3 · Institutional infrastructure platform

Microsoft-like: safe to buy, configure, deploy, govern, integrate and operate for years.

- Tenant control plane
- RLS and authorization
- SSO/SCIM
- Roles/capabilities
- Approval workflows
- Audit and evidence
- Integration gateway
- LTI/OneRoster/Edu-API
- Migration and reconciliation
- Feature flags and rollout
- Billing
- Trust/compliance
- SLOs/incidents
- Backup/restore/offboarding
- Developer ecosystem

## What to borrow, and what not to copy

| Model | Borrow | Semester equivalent | Do not copy |
| --- | --- | --- | --- |
| Apple | Integrated experience, design discipline, privacy posture, premium support | Calm student OS, cohesive navigation, accessibility, offline-safe, student-controlled sharing, quality mobile | Closed ecosystem, forced lock-in, opaque platform rules |
| Google | Search, cloud, identity, AI, data systems, developer distribution | Education search, education graph, membership layer, AI gateway, APIs, partners | Ad-tech incentives on student data, uncontrolled aggregation |
| Microsoft | Enterprise identity, productivity, administration, procurement readiness, long contracts | Tenant admin, SSO/SCIM, workspace, compliance controls, implementation, annual licensing, marketplace | Complex enterprise UX, configuration overload, fragmented surfaces |
| Canvas/Brightspace | Course workflow and institutional deployment | Course Studio connected to planning, actions, support, AI, career | Course experience isolated from the wider journey |
| SIS/ERP vendors | Record authority, policy, transaction integrity | Canonical academic domains, deterministic rules, audit, migration, reconciliation, rollback | Legacy UX, closed integrations |
| ChatGPT/Claude/Perplexity | Conversational intelligence and research | Governed copilot, policy-aware routing, citations, academic context, human escalation | Treating model output as official truth |

## Deployment ladder

Development → Tenant-safe test environment → Sandbox integration → Preview deployment → Internal beta → Private beta tenant → Pilot tenant → Controlled production cohort → Annual customer deployment → Multi-campus expansion

Each step requires: Configuration, Policy approval, Security review, Accessibility review, Data validation, Integration test, Rollback plan, Support readiness, Monitoring, Release evidence, Owner approval.

## Expansion stages

1. Daily student OS + registration readiness
2. Course Studio + advising/support workflows
3. Institution control plane + integrations + rollout factory
4. Native registrar/academic domains where authorized
5. Campus services + student account + career + family
6. Developer platform + marketplace + global ecosystem
7. Education infrastructure company: identity, cloud, AI, operating layer, standards, partners, global, lifelong learners
