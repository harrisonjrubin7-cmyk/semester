Developer guide

Set up, build, test and ship. v0.1, October 2026.

1. Repos and code in this project

  • harrisonjrubin7-cmyk/semester: the product app (ground truth).
  • handoff/semester-platform/: database migrations with RLS, typed API routes, and tests for community, marketplace and ops (new).
  • handoff/semester-core/: pure logic (access, AI gateway, approvals, freshness, provenance), with tests.
  • handoff/claude-code-toolkit/: design-system sync skills and the audit script.
  • handoff/workflow-router-app/: a full Next.js + Supabase reference app.

Code files in this project end in .txt so they don't execute here. Strip the suffix when you copy them into a repo.

2. Local setup

git clone git@github.com:harrisonjrubin7-cmyk/semester.git && cd semester
npm install
npx supabase start            # local Postgres + auth
npx supabase db reset         # runs migrations + seed
cp .env.example .env.local    # fill SUPABASE_URL / ANON_KEY
npm run dev

3. Conventions

  • TypeScript strict. Validate every input with Zod at the boundary.
  • UI uses design-system tokens only (styles.css). No raw hex values in components.
  • Every query runs as the user (anon key + JWT). The service role is only for workers.
  • Every mutation writes an audit row: actor, role, institution, action, target, before/after.
  • Copy follows the readme's voice rules: sentence case, the status sentence, no overclaims.

4. Branching and release

  1. Branch from main, named feat/… or fix/….
  2. Open a PR. Vercel builds a preview, and CI runs lint, typecheck, unit tests, RLS tests and the design-system audit.
  3. One review is required, and the founder approves anything touching migrations.
  4. Merge to main, which deploys to staging. Promote to production after the smoke check.

6. Adding a feature (checklist)

  1. Migration with RLS policies and RLS tests.
  2. Zod schema and a typed route handler or server action.
  3. UI built from design-system components, with every state: empty, loading, error, offline.
  4. Audit write and telemetry event.
  5. Feature flag per institution.
  6. Docs: update the user guide section and the master catalog status.
