Architecture guide

For architects and senior engineers. v0.1, October 2026. A design-level description: verify everything against the repo (harrisonjrubin7-cmyk/semester) before relying on it.

1. Principles

  1. The institution is the system of record. Semester reads, displays its provenance, and writes back only through approved paths.
  2. Student records never reach an AI model. This is enforced in the gateway, not by convention.
  3. Company roles never see student data. This is enforced by RLS and separate schemas.
  4. Every consequential action is previewed, attributed and logged.
  5. Status over claims. Freshness and source are shown on every record.

4. Data model (summary)

Tenancy: every row carries institution_id; RLS policies check it against the JWT claim. The edu schema holds student records (enrollments, holds, grades as shown, advising notes). community and market hold user-generated content, linked to a profile and never to edu tables. ops holds company data with no student identifiers. See handoff/semester-platform/supabase/migrations/.

5. Security boundaries

  • RLS on every table; service-role keys only in workers, never in the browser.
  • AI gateway allow-list: course content, the student's own typed text, public catalog data. Blocked: anything from edu.*.
  • Marketplace and messages: rate limits, a report pipeline to the moderation queue, an integrity classifier on listings.

6. Key flows

SIS sync

  1. Worker pulls a delta.
  2. Normalise.
  3. Upsert with source and synced_at.
  4. Reconcile against the previous snapshot.
  5. Mismatches go to the registrar queue.
  6. Rebuild the affected read models.

Ask Semester

  1. Request.
  2. Policy check (course AI policy).
  3. Build the context from allowed sources only.
  4. Redact.
  5. Model call.
  6. Cite sources.
  7. Label the answer AI-assisted.
  8. A person confirms any action.

Marketplace sale

  1. Listing.
  2. Integrity and safety check.
  3. Live.
  4. Offer.
  5. Processor checkout.
  6. Pickup confirmation releases the payout.
  7. Any dispute goes to T&S.

8. Decisions (ADRs)

  • ADR-001: Postgres RLS as the primary authorisation layer.
  • ADR-002: read models over live SIS queries, for speed and to show freshness.
  • ADR-003: the AI gateway as the single egress point to models.
  • ADR-004: marketplace payments through a processor; no money transmission.
  • ADR-005: company ops data in a separate schema with no student identifiers.
