# Algorithm governance

_Semester design, intelligence, workflow and data system · 2026-10-05 · Source: uploads/expand further on brand identy algorthims workflow.pdf, reconciled with this design system (readme.md, tokens/, components/). Where they differ, this design system wins and the difference is listed._

> Semester should make an institutionally complex world feel personally clear.

Explainable, policy-bounded, source-aware, purpose-limited. No black box makes a high-impact educational decision.

## Every algorithm records

- Purpose, owner, users affected, decision type
- Input data and excluded data
- Source authority, data classification, tenant policy, consent requirement
- Output, confidence/uncertainty, explanation
- Human review path, appeal/correction path
- Bias/fairness review, monitoring, evaluation dataset
- Version, audit record, rollback/deprecation plan

## Never used without explicit policy or consent

Private message content · sensitive health data · protected characteristics · financial aid detail beyond the action · accommodation details · disciplinary records · external browsing · unapproved behavioural surveillance.

## Hard limits

No algorithm makes a clinical, disciplinary, emergency or financial decision; it routes to the approved official process. Workload and risk signals never trigger punitive institutional action.
