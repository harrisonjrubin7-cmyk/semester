# Architecture

The system has four durable layers: encrypted original objects, normalized source chunks and citation records, relational course knowledge, and versioned study/calendar outputs. PostgreSQL owns the truth; JSONB-style JSON columns hold flexible extracted and generated structures. Redis/Celery handles extraction and generation work. MinIO provides the production-shaped local object-store service.

The processing path is: validate declared size/extension/checksum → preserve the private original → verify object owner, bucket, key, actual size, content, checksum, and encryption → persist one idempotent completion receipt and extraction job → quarantine → malware scan → recheck checksum → specialized extractor → location-bearing chunks → citation records → structured fact/generation adapters → citation validation → review/conflict records → confirmed calendar and study assets → PDF/DOCX/ICS renderers.

The development LLM returns no facts when evidence is absent. A production adapter must implement `StructuredLLMClient`, validate each Pydantic response, retry bounded transient failures, and reject unknown citation IDs before persistence.

Security boundaries include JWT authentication, per-query ownership checks, duplicate checksums, object-store owner pinning, completion receipts, safe ZIP extraction with traversal and expansion limits, explicit supported extensions, soft deletion, and an injectable malware scanner. An accepted upload is `quarantined` until the worker records `scanning`; extraction begins only after the scanner succeeds. Production still requires managed encryption/KMS, real AV scanning, rate limiting, audit logging, signed downloads, secret management, and tenant-level operational review.

The completion receipt is also a transactional dispatch outbox. API retries and the periodic dispatcher atomically claim undispatched or stale rows and publish with the stable database job ID as the Celery task ID. Workers atomically claim bounded leases, increment a fencing generation on each reclaim, and condition every progress or terminal database write on the current generation. Celery beat redelivers expired extraction and study-generation leases; cancellation and source/target deletion prevent stale callbacks from committing. Provider calls remain at-least-once: adapters must use the stable logical-job idempotency key where supported, and no exactly-once network-effect claim is made.

Intake limits are centralized in runtime settings. The conservative default is 100 MiB for an upload and for any individual archive member, 100 central-directory entries per ZIP, and 500 MiB of cumulative expanded data. This 100 MiB default is the governing boundary where older planning material mentioned 200 MiB. Local uploads stream into a sibling temporary file and replace the preserved object only after a complete bounded transfer; ZIP extraction likewise stages and commits only after every member passes preflight and streamed-size checks. Malware scanning remains ahead of archive extraction in the worker pipeline.
